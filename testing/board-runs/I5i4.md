# I5i4: the every-boot check, the bundle's command line, and lemnosd's check

Untested on board. Nothing here has run on a board. Every test named below runs on this PC over
real files in temporary directories, a FAT image built in memory, and fakes for the mount, the
boot calls and the block device. A board run is needed for the points below.

## Points to be run on a board

| # | Point | Where it is written | Check |
|---|---|---|---|
| 1 | The boot partition's FAT volume is read raw and the files come back as the bundle wrote them (short and long names, a file over several clusters) | `bootfat::read_file` against a real FAT16 or FAT32 partition | Install a slot; from the initramfs or a shell, read `slots/<id>/kernel8.img` through the reader and compare its SHA-256 with `slot.json`. |
| 2 | slot-init's every-boot check passes for an untouched slot, and refuses a one-argument edit to `cmdline.txt` | `service/slot-init/src/boot.rs` (`verify_boot_files`) | Boot a slot; then append `mem=128M` to its `cmdline.txt` on the boot partition, reboot, and read the log. The default must not start; the state must name `cmdline.txt`. |
| 3 | The data partition is found by the label `lemnos-data` | `service/slot-init/src/boot.rs` (`find_data`) | Label the data partition with `e2label`; boot. Then give a second partition the same label and boot: the log must name both partitions and the board must not guess. |
| 4 | On raw NAND the data volume `data` is found on `ubi0` | `service/slot-init/src/boot.rs` (`on_nand`) | On a NAND board, boot; check the mount line names `ubi0:data`. |
| 5 | lemnosd's check before a restart refuses the restart when neither slot matches, and repoints when only the default fails | `drivers/system-slots/src/boot_guard.rs` | With both slots' `cmdline.txt` edited, request a reboot: the restart is refused and the state's error names both. With only the default edited, request a reboot: `default.txt` names the previous afterwards. |
| 6 | The slow period catches an edit with no restart requested | `drivers/system-slots/src/lib.rs` (`slow_check`) | Edit the default's `cmdline.txt`; wait ten minutes; read the state's error and `default.txt`. |
| 7 | The boot partition is read through the running system's mount on raw NAND (UBIFS), and the same check passes there | `service/slot-init/src/boot.rs` (the NAND branch of `verify_boot_files`) | Boot a NAND board; the log has no boot-file mismatch for an untouched slot. |
| 8 | The read of a kernel-sized file (tens of MB) finishes within the boot's time budget, and its memory is bounded by `bootcheck::LIMIT` | `bootfat::read_file` and `bootcheck::check` | Time the initramfs boot with the check; note the time added on the CM5 and the peak memory. |

## What a run does

For each point: the step, the expected result, and the result read, with the firmware version from
`vcgencmd version` and the image's build. A point that fails is recorded with its output; the
check is not turned off to make a run pass.

## Known gaps (not run; decided, recorded here)

- The U-Boot form's `extlinux.conf` is generated at install from the command line and is not in the
  manifest. An edit to that file is not caught by the check.
- lemnosd's repoint is a whole-file write of the boot record, not the one-sector write the design
  names for the Raspberry Pi pointer files.
- A mismatch on the default falls back through the existing candidates (a trial of another verified
  slot), not through a pointer write to the previous.
- When no slot matches, slot-init still waits and restarts (the existing rescue), so a board with
  both slots bad restarts after the rescue wait rather than staying up in the initramfs.

## Pass criterion

- Points 1 to 4: the results match the expected values.
- Points 5 and 6: the state and the pointer match the table.
- Point 7 and 8: no false mismatch on an untouched slot; the added time is recorded.
