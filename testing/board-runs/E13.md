# E13 board run: ISP600 load image and statistics

Status: untested on board.

No A733 board was reachable from the session that built `drivers/isp600`,
`drivers/isp600-sys` and `contracts/isp-isp600`. Everything there passes its tests against a
stand-in kernel and mocked streams, and both layout checks match the vendor headers when compiled
with a C compiler. What follows is what a local session checks once a board is reachable. Take the
board lock named in `AGENTS.md`. Build on NVMe or SSD, never on the Github HDD.

## Source of the interface facts

radxa/allwinner-bsp on GitHub, branch `cubie-aiot-v1.4.6` at
`2045a3ca2a01f088c0314dc924bda59d154e363e` (GPL-2.0; facts only, no code copied):

- `include/uapi/media/sunxi_camera_v2.h`: the four private requests and their structures.
- `drivers/vin/vin-isp/isp600/isp600_reg_cfg.h`, `isp600_reg.h`, `isp600_reg_cfg.c`: the load
  image (0x7700 bytes), the statistics (0x6a00 + 0x3300 bytes), the register offsets.
- `drivers/vin/vin-isp/sunxi_isp.c`: `VIDIOC_VIN_ISP_LOAD_REG` and when a loaded image takes
  effect (the PARA_LOAD interrupt).
- `drivers/vin/vin-stat/vin_h3a.c`: `H3A_CFG`, `STAT_EN`, `STAT_REQ`.

Two facts are inferred, not stated: the order of the statistics parts on each side of the first
histogram (the offset 0x5a80 is stated; which parts lie before it is fixed by their sizes), and
`settle` (3 by default, from reading when the kernel copies an image and saves statistics).

## What has to hold first

- The vendor kernel's `vin` driver is bound with its ISP. Record `media-ctl -p`, with the names of
  the capture node (`vin_video<n>`), the ISP subdevice (`sunxi_isp.<n>`) and the statistics
  subdevice (`sunxi_h3a.<n>`) on one pipeline.
- The vendor's own ISP user-space service is not running (it would load images and take
  statistics too).
- A board file entry:

  ```toml
  [[devices]]
  id = "isp0"
  driver = "isp600"
  config = { capture = "vin_video0", isp = "sunxi_isp.0", statistics = "sunxi_h3a.0" }

  [devices.streams.config]
  buffers = 4
  buffer_bytes = 30464

  [devices.streams.statistics]
  buffers = 4
  buffer_bytes = 40192

  [devices.streams.output0]
  buffers = 4
  buffer_bytes = <at least the output layout's size>
  ```

## Checks

1. **Request numbers and sizes.** `start` succeeds. Pass: `H3A_CFG` answered 0x6a00 (start
   refuses anything else), `STAT_EN` and the first `LOAD_REG` return 0. Record `dmesg` for the vin
   driver across the run: no refusals.
2. **Granted format.** For NV12 at 1920x1080, record `v4l2-ctl -d <capture node> --get-fmt-video`
   after `start`. Pass: bytes per line equal the width and size image equals the layout's size
   (the driver refuses otherwise). If the node pads lines, record by how much: the driver's
   stride rule then needs widening.
3. **Statistics size.** Pass: every published statistics frame is 40192 bytes and the first 0x100
   bytes hold the saved registers (compare words 0x00..0x100 with what the kernel prints with its
   register dump, if enabled).
4. **Layout regions on the block.** Point the camera at a half black, half white card. Load an
   image built from the register offsets alone (no vendor tuning data or library: zeros, the
   statistics modules on, the windows set) and record the statistics. Then change only the AWB
   window registers. Pass: only the AWB region (offset 0x480, 0x1800 bytes) changes its pattern;
   AE (0x100), the five AF parts and the histograms keep theirs. Repeat moving the histogram
   window: the change shows at 0x5a80. This confirms the inferred order around the first
   histogram. If an image built that way gives no statistics at all, record it: the block then
   needs register values only a tuning set carries, and that stays with the camera stack.
5. **Settle.** Load two images that differ only in a strong digital gain, alternating, one job per
   frame with `settle` 0, and record for each job the mean of its image and which load it matches.
   Pass: find the smallest `settle` at which every job's image and statistics match its own load.
   If it is not 3, `DEFAULT_SETTLE` changes to the measured value.
6. **Address words.** Post an image with a nonzero byte in word 0x140. Pass: the job is counted as
   dropped, nothing reaches the kernel (no `LOAD_REG` in an `strace` of the daemon), the stream
   keeps running.
7. **Recovery.** Unbind and rebind the vin driver while streaming. Pass: health goes degraded,
   attempts back off to 8 s, and streaming resumes after the rebind with no restart of the daemon.
8. **Allocation.** Stream 3000 jobs. Pass: the daemon's resident size is flat after the first
   hundred.
