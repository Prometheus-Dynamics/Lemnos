# K1a4 board run: the VEPU580 H.265 encoder through `rk-mpp:rkvenc2` (`lemnos-driver-rkvenc`)

Status: untested on board. Nothing here was read or written on a device. The layouts are pinned to
the header with gcc and clang; the job is checked on rk-mpp's played kernel and by the codec.block
chain test.

This encoder is not on the reference CM5 board. The run needs a board with a VEPU580 node behind
the vendor kernel's `/dev/mpp_service`, bound to the `mpp_rkvenc2` platform driver (and not to
`mpp_rkvenc`, which would make the claim ambiguous and refused). Build on NVMe or SSD, never on the
Github HDD. Module loads and unbinds are allowed; report each.

## Checks

1. **Identity.** Read `reg0000` (word 0, `base::reg0000`) through the service once the claim is
   bound. Pass: `HEVC_CAP` (bit 9) is 1 and `IP_ID` (bits 24 to 31) is the value the K1a2b run
   reads for the same block. Any other value: stop.
2. **Status read-back.** Submit one job with only `RECON32_CKG` set (word 22, BASE class, the H.265
   control word `rdo_ckg_hevc`) and no address. Pass: the completion returns without a fault and the
   status class (words 4096 to 4275, `st` modules) reads back.
3. **One encode.** Submit one H.265 job: a frame's source buffer as `ADR_SRC0` (word 160, PIC
   class, translated) at offset 4096 of a claim buffer, and the rest of the job's values from a
   fixture. Pass: the job completes, the job's table has one entry, index 0, relative to the PIC
   class, and the status class reads back with a non-zero `bs_lgth_l32` (word 4096). Record the
   stream length.
4. **OSD and debug are not reached.** Nothing in this run writes the OSD or debug class. Pass: the
   OSD words read back as they were before the job.

Record each result with the kernel version, the board's device tree compatible string, and the
output of each check.
