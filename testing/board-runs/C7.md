# C7: the Linux backend through the module, on a board

Run on the board 2026-11-11: checks 1 to 3 passed; check 4 not run (no SPI device).

On the CM5, with `lemnos.ko` loaded and a SPI device bound through `driver_override` and `owned=`:

1. Start `lemnosd` with a real board file. `ls -l /proc/$(pidof lemnosd)/fd` shows `/dev/lemnos` and one `[lemnos-claim]` per device, and no `/dev/i2c-*`, `/dev/spidev*` or `gpio-line`.
2. The drivers that ran stock still report their values.
3. Unload the module with `lemnosd` stopped and start it again: the same board file runs on the stock nodes.
4. Bind one SPI device back to `spidev` and start it again: that device alone is on its stock node.

## Result, 2026-11-11

Run 2026-11-11 on the CM5 (Raspberry Pi Compute Module 5 Rev 1.0, Raze #2), kernel `7.2.9-v8-16k`,
with `lemnos.ko`, `lemnosd` and the tools from PR F2a, built on NVMe and copied to
`/tmp/lemnos-run/` on the board. Raw logs are kept off the repository.

`lemnosd --board c7-board.toml` with the product's own service stopped: `ina2xx` (INA238,
`i2c-1` 0x40), `bmm150` (`i2c-1` 0x10), `bmi088` on `pio-i2c:sda=8,scl=7`, `hwmon-fan` (`pwmfan`)
and `thermal-zone` (`thermal_zone0`).

1. Module loaded: the daemon's file descriptors are `/dev/lemnos`, two `[lemnos-claim]` (the two
   `i2c-1` chips) and `/dev/pio0`, and no `/dev/i2c-*`. The PIO I2C goes to the stock node: the
   backend has no module route for it.
2. Values on the module route: bus 4.40 V, 2.28 W; the magnetometer's three axes; acceleration x
   about 9.83 m/s² and the gyroscope; fan duty 0.702 (no tachometer); 42 °C. Right after start
   the list shows the power monitor degraded and the magnetometer failed until the first read
   powers them up; reads then answer. Once, on the first run, the IMU answered `-5` and then `-95`
   during its power-up; twelve reads on each route afterwards showed the normal power-up (`AGAIN`,
   then data), and it was not seen again.
3. SIGKILL of the daemon and a restart: both claims taken again without `EBUSY`. Module unloaded
   and the daemon started again: `/dev/i2c-1` twice, the same values.
4. Not run: the board has no SPI device that may be touched.
