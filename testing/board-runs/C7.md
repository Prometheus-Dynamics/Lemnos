# C7: the Linux backend through the module, on a board

Untested on board. The QEMU run covers every route against `i2c-stub`, a memory-backed test adapter, a loopback SPI controller, `gpio-sim` and a test PWM chip.

On the CM5, with `lemnos.ko` loaded and a SPI device bound through `driver_override` and `owned=`:

1. Start `lemnosd` with a real board file. `ls -l /proc/$(pidof lemnosd)/fd` shows `/dev/lemnos` and one `[lemnos-claim]` per device, and no `/dev/i2c-*`, `/dev/spidev*` or `gpio-line`.
2. The drivers that ran stock still report their values.
3. Unload the module with `lemnosd` stopped and start it again: the same board file runs on the stock nodes.
4. Bind one SPI device back to `spidev` and start it again: that device alone is on its stock node.
