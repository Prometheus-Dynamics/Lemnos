# B10 board run: orientation on a CM5

Status: untested on board. The filter and the driver's read path are covered by unit
tests (`drivers/orientation`), with the filter's tests carried from the `dev` branch. No live IMU
reading has reached the driver on a real board.

Setup: a CM5 with a real accelerometer and gyroscope on one IMU device, and a magnetometer for the
nine-axis checks. Run the same physical board against both this driver and the `dev` branch's fusion
device, and compare the two outputs. Take the board lock named in `AGENTS.md` before starting. Build
on the NVMe or SSD, never on the HDD.

Board file for this driver (the IMU and magnetometer names are the board's own):

```toml
[[devices]]
id = "orientation"
driver = "orientation"
uses = { accel = "imu", gyro = "imu", mag = "mag" }
config = { sample_rate_hz = 100, mode = "9axis" }
```

`sample_rate_hz` is the rate the run reads the orientation device at. The driver has no clock, so the
run must read at exactly that rate (see the note on time in `drivers/orientation/src/lib.rs`). Use
`mode = "6axis"` for the six-axis checks.

1. Build the driver for aarch64, bind it with the IMU present, and read it at 100 Hz for 10 s.
   Pass: bind succeeds and the reads succeed.
2. Lay the board flat and still, and read for 30 s. Run `dev`'s fusion device on the same board at
   the same time.
   Pass: roll and pitch are within 0.5 degrees of `dev`'s values at every read after the first 5 s.
3. Tilt the board to a known roll of 30 degrees and a pitch of 20 degrees, hold for 10 s, and compare
   with `dev`'s output.
   Pass: roll and pitch are within 1 degree of `dev`'s values once settled.
4. Rotate the board through a full turn about its vertical axis at a steady rate, with the magnetometer
   in use, and read at the configured rate.
   Pass: yaw matches `dev`'s yaw within 2 degrees at four headings (0, 90, 180 and 270 degrees, against
   a bench compass).
5. Read at half the configured rate (50 Hz against `sample_rate_hz = 100`) through the same turn.
   Pass: the yaw is about half of the true rotation, which confirms the driver takes its time step from
   the configured rate and not from the caller. Record the value. Then restore the 100 Hz read rate.
6. Disconnect the accelerometer's I2C wiring for 2 s during reads, then reconnect it.
   Pass: each read during the outage fails with an error, and health reports `Degraded`. After
   reconnecting, the output matches a run with no outage (the filter does not integrate across the gap)
   within 1 degree.
7. Time 1000 reads of the orientation device on the CM5, with both sensors present, and record the
   median and worst case here.
   Pass: every read completes, and the timings are recorded. CM5 timings only.
