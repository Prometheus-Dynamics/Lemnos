# I3: every stream timestamp on CLOCK_MONOTONIC

Status: untested on board. Stream frame timestamps, value stamps and the `now_ns` a driver's tick
is given are `CLOCK_MONOTONIC` nanoseconds on Linux. `lemnosd`'s host clock reads
`CLOCK_MONOTONIC` (it counted from the daemon's start before). Drivers reading a V4L2 node pass on
a buffer's timestamp only when the node flags it `V4L2_BUF_FLAG_TIMESTAMP_MONOTONIC`, and otherwise
the time it was dequeued. The kernel module already stamped with `ktime_get_ns()`.

What has run on the PC: unit tests (the host clock and the backend's clock bracketed by
`clock_gettime(CLOCK_MONOTONIC)`, the V4L2 timestamp rule for each clock flag) and the QEMU harness
with the module's test source, whose 8 frames were each stamped between two
`clock_gettime(CLOCK_MONOTONIC)` readings of the consumer; the same check fails when the source
stamps with the wall clock. No frame from real hardware has been checked.

Before running: take `/run/lock/board-gpu.lock`. Builds go on NVMe or SSD, never on the Github
HDD.

## 1. Receiver frames through the module

Run the camera proof (`testing/crates/camera-proof`) on the reference board's camera. For 100
frames, record `clock_gettime(CLOCK_MONOTONIC)` when each frame is taken from the ring. Each
frame's timestamp must be below that reading and above the previous frame's, and the gap must be
under two frame periods.

## 2. A V4L2 capture node

On a board with a V4L2 capture driver bound (`v4l2-capture`, `rkisp` or `isp600`), do the same
for 100 frames. Record whether the node flags its buffers `TIMESTAMP_MONOTONIC`
(`v4l2-ctl --stream-mmap --verbose` shows the flags). With the flag, the frame's time is the
node's; without it, the time the driver dequeued it, so the gap to the reading is at most one
tick.

## 3. A tick-stamped completion

Post one job to a scaler or codec stream (`image.scaler/1` or `codec.block/1`) and check its
completion's timestamp lies between `CLOCK_MONOTONIC` read just before posting and just after the
completion arrived.
