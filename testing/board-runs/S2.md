# S2: the board security switch, on the reference board

Untested on board. Run this on the reference board (CM5, Raze #2) in a local session, with the
board lock, after the S2 pieces merge. Nothing here touches the board's disks: the record and the
view live on tmpfs and in a scratch directory the run makes itself.

## What to show

1. Install the daemon and the packages from this revision. Put the board file's `security` device in
   (`driver = "system-security"`, `uses = { slots = ..., flash = ... }`, `config = { orion = false }`, with `record` and `keys` in the board file's `[security]` table).
   Pass: `lemnos-ctl list` shows `security` running.
2. `lemnos-ctl security security state`: `switch off`, `generation 0`, `view current`. Pass: absent
   record reads off, and the view is in `/run/board/security`.
3. `lemnos-ctl security security precheck on` with no trust root: `missing:` lines name the keys
   list. Pass: nothing is changed (`state` still reads off, generation 0).
4. With a trust root and a verified default and running slot: `precheck on` says `ok`. Then
   `lemnos-ctl security security on`: the record's generation is 1, `/run/board/security` reads
   `on` and `generation 1`, and `/etc/board/security` (through the image's link) reads the same.
   Pass: a slot-driver install with an unsigned bundle is refused by name while the switch is on,
   with no daemon restart (the daemon's process id is unchanged: `pidof lemnosd` before and after).
5. Turn it off again: `lemnos-ctl security security off`. Pass: the unsigned bundle installs.
6. During an install (a large bundle streamed over the socket), `security on` and `security off` are
   refused by name with `busy:` lines. Pass: nothing is changed.
7. Power cut during step 4 (after the record write, before the render): on the next boot,
   `lemnos-ctl security render --record <scratch>/security.rec --dir /run/board` renders the record's
   value. Pass: the view matches the record.
8. A corrupt record (overwrite one copy and the other with junk, the file is kept): the view reads
   `on`, `record corrupt`. Pass: the default slot still starts (never-strand).

## Recording the run

Write the results under this file's heading, with the output of each `lemnos-ctl` call, the
daemon's process id before and after step 4, and the board's kernel version. CM5 timings only.
A failed step is written down with its output and is not re-run quietly.
