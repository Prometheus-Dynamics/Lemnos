# A35 board run: register reads on a host-owned I2C device

Status: untested on board.

A35 lets a host-owned device's driver read registers on I2C (a register address of the width the
driver declares, then a read) and refuses every other write. Everything here ran on the simulated
bus only. The check on a real machine:

1. Pick an I2C power monitor or magnetometer that the kernel's own driver has bound (for example an
   `ina2xx` hwmon device, or a `bmc150_magn` IIO device). Record its bus and address, and dump its
   registers with `i2cdump -y <bus> <addr> w` (or `b`) while the kernel driver holds it; note which
   registers move on their own (data, status).
2. Add it to the board file with the matching driver (`ina2xx` or `bmm150`), `owner = "host"`, and
   for `ina2xx` the shunt the kernel's device tree names. Start `lemnosd`. The device reaches
   `Running`.
3. Read it a few hundred times (method 1). The values agree with the kernel's own (`in*_input`,
   `curr1_input`, `power1_input`, or the IIO channels) within the chip's resolution.
4. Stop `lemnosd` and dump the registers again. Every configuration and calibration register is as
   in step 1; only the registers noted as moving on their own differ.
5. While `lemnosd` reads in a loop, read the kernel's values in another loop for a minute: none of
   the kernel's reads fails or returns a value from the wrong register (the kernel's drivers
   address each register in the same transfer as its read, as Lemnos does).
6. Optional: put a driver that configures on bind on the same device with `owner = "host"`
   (`generic-sensor` with an `init` step): it reads its identity and never writes, and step 4's
   comparison still holds.
