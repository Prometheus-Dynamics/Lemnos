# L3 board run: the root phase and the drop on a real board

Status: untested on board.

The root phase (`lemnosd --user lemnos --group lemnos`, and `lemnos-orion` with `LEMNOS_ORION_USER`) is
checked here by its unit tests, by the user-namespace test, and by the built daemon under `unshare -Ur`
up to the group step. Those do not show the drop as root in the initial user namespace, the device
groups, or the two init systems. This record is for a board image with the files of `packaging/` installed.

Preparation (on the image, as root; nothing here runs on the development PC):

1. Create the users and groups: systemd-sysusers from `packaging/systemd/lemnos.conf`, or on BusyBox the
   passwd, group and shadow lines in `packaging/README.md` ("Without systemd").
2. Install `/usr/bin/lemnosd` and `/usr/bin/lemnos-orion` (if shipped), the udev rules or the mdev fragment,
   the board file at `/etc/lemnos/board.toml`, and the environment files from `packaging/systemd/`.
3. Do not set `RuntimeWatchdogSec=` or `ShutdownWatchdogSec=` in systemd, and run no `watchdog` daemon.

Checks, in order:

1. The root phase runs and the drop lands. Start the daemon (`systemctl start lemnosd`, or
   `/etc/init.d/S50lemnosd start`), then read its process:
   - `grep -E '^(Uid|Gid|Groups|CapInh|CapPrm|CapEff|CapBnd|CapAmb|NoNewPrivs)' /proc/$(pidof lemnosd)/status`
   - expected: `Uid` and `Gid` all equal to `id -u lemnos` and `id -g lemnos`; `Groups` the empty list; `CapInh` 0; `CapAmb` 0;
     `CapPrm` and `CapEff` both `0000000000020000` (bit 17, `CAP_SYS_RAWIO`); `CapBnd` with bit 17 only
     (`0000000000020000`); `NoNewPrivs` 1.
2. The socket is the daemon's: `ls -ld /run/lemnos` shows owner `lemnos`, mode `750`, and
   `ls -l /run/lemnos/lemnosd.sock` shows group `lemnos`, mode `660`. `lemnos-ctl list` works from a user
   in group `lemnos`, and is refused for one that is not.
3. The device nodes open. Each node the board's drivers use is owned by group `lemnos` (`ls -l /dev/...`);
   `lemnos-ctl list` shows each device bound, not `failed` with a permission error.
4. A refused start is refused. Set `--user nosuchuser` (in the unit's ExecStart or in the script), start,
   and expect `no user named "nosuchuser"` on the error output (`journalctl -u lemnosd`, or
   `/var/log/lemnosd.log` under BusyBox), and no socket. The supervisor then retries after 1 s, as for any
   exit: the record is the message each time, not a stop.
5. The register mapping keeps working through the kept capability: a block whose registers are mapped
   through `/dev/lemnos` binds (the driver's `read` returns, not `PermissionDenied`).
6. The restart stays inside the watchdog bound: `kill -9 $(pidof lemnosd)` (or the child pid under
   BusyBox), then time to the new `Uid` line and to the socket again. Expected: under 15 s, with the
   1 s restart. The hardware watchdog must not reboot the board in that time.
7. The bridge drops too: `lemnos-orion` (or `S51lemnos-orion`) shows, in `/proc/<pid>/status`, the
   `LEMNOS_ORION_USER` uid and the groups in `LEMNOS_ORION_GROUPS`, `CapEff` 0, and `NoNewPrivs` 1.
8. The privilege path is one path: the unit and the script pass `--user`, and `setcap` is not used:
   `getcap /usr/bin/lemnosd` prints nothing.

Record each check's output here. Board timings: CM5 only (per the board-run rules), in
`testing/board-runs/L3.md`.
