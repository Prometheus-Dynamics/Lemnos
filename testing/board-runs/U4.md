# U4 board run: ISP600 tuning, record enable keeps its word, table and statistics places

Status: untested on board.

No board was reachable from the session that wrote this. The layouts and the tests are in
`drivers/isp600/src/library_tests.rs` and `drivers/isp600/src/tuning.rs`; they pass with the
`device` feature off and check no hardware. What follows is what a local session checks once a
board is reachable. Take the board lock named in `AGENTS.md`. Build on NVMe or SSD, never on the
Github HDD.

## Sources

- `radxa/allwinner-isp6xx` at `516fd7443810e0807b289829dbae1ae5a62e0cb5`: `isp6xx/libisp/isp_manage/isp_manage.c`
  (`__isp_alloc_reg_tbl`, the default register words for ISP 602) and `isp6xx/libisp/include/isp_comm.h`
  (the table and statistics sizes and offsets). `scripts/mksetup.sh` maps the A733 to ISP 602.
- `radxa/allwinner-bsp` at `2045a3ca2a01f088c0314dc924bda59d154e363e`: `isp600_reg.h`, as in `U3.md`.

## Checks

1. Default words, read back. Load an image whose registers are the library's defaults for the
   channel expand words (`0x000c00c0` at each channel's register) and for `D3D_CFG0` (`0x0400008a`).
   Read the block's registers back after the load (the vendor's register dump) and compare. The
   channel words must read `0x000c00c0`; `D3D_CFG0` must read `0x0400008a`, with bit 0 clear.
2. Record enable keeps the other bits. With the record enable on, `D3D_CFG0` must read
   `0x0400008b`, and off again `0x0400008a`. A difference in bits 1, 3, 7 or 26 means the setter
   and the block disagree on those bits; report the register dump.
3. Table places. With the library's table places (`D3D_DK`, `PLTM_TM`, `PLTM_LM`, `DRC`,
   `GAMMA` and the front end's channel tables; `drivers/isp600/src/layout.rs`), write a known
   pattern into one table, load, and read it back from the kernel's own table dump or from a
   frame's effect. Record the first table whose place differs.
4. Statistics places. Read one statistics part of a frame, for example the AE part at offset
   `0x100`, and confirm its contents match the layout's offsets (`STATISTICS_REGIONS`).

## Not checked here

- The decoded statistics. The library's decode is only in its prebuilt binary, so no part of the
  statistics is decoded by Lemnos, and no check is written for one.
- White balance, colour matrix, gamma, tone, lens shading, spatial denoise and sharpen words. They
  are not encoded here; see `docs/drivers.md`, "ISP600 tuning".
