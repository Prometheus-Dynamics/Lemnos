# V1b3: ranges, steps and warning limits of the built-in items, on the reference board

Untested on board. The limits come from the board file, and the watchdog's range is read from
sysfs at bind. The driver tests run on fake sysfs trees and the mock I2C bus; no device was read.

## The check

On the reference board, with the board file as `docs/boards.md` gives it (the keys `max_rpm` and
`warn_below_rpm` on the fan and the channel fan, `bus_warn_below_v`, `bus_warn_above_v` and
`current_warn_above_a` on the power monitor, and the thermal zone's `min_c`, `max_c`,
`warn_below_c` and `warn_above_c` where a zone is configured):

1. `lemnos-ctl show` for each device. Each item shows the range, step and limits of
   `docs/drivers.md`, "Ranges, steps and limits"; an item with no board key shows none.
2. The hardware watchdog's `timeout` shows the device's `min_timeout` to `max_timeout`, and
   `timeleft` shows 0 to `max_timeout`. Compare with `cat /sys/class/watchdog/watchdog0/*timeout`.
3. The fan's `rpm` read with the fan at full duty stays below `max_rpm`; with the fan stopped it
   falls below `warn_below_rpm`, and the description reports the warning.

## What to record

The panel output for each device, the watchdog's sysfs values, and any reading outside the range
the board file gives. Results go here, with the output pasted.
