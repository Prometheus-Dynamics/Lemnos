# U3 board run: ISP600 tuning encodings and extent refusal

Status: untested on board.

No A733 board was reachable from the session that wrote the encodings in `drivers/isp600/src/tuning.rs`
and the extent check in `drivers/isp600/src/layout.rs`. The unit tests pass, and the bit layouts match
the vendor header when compiled with a C compiler. What follows is what a local session checks once a
board is reachable. Take the board lock named in `AGENTS.md`. Build on NVMe or SSD, never on the Github HDD.

## Source

radxa/allwinner-bsp at `2045a3ca2a01f088c0314dc924bda59d154e363e` (GPL-2.0; facts only):
`drivers/vin/vin-isp/isp600/isp600_reg.h` (the `CH0` to `CH2` expand registers, `MODULE_BYPASS1`,
`D3D_CFG0`, `D3D_LBC_CFG0` to `CFG5`, `INPUT_SIZE`, `VALID_SIZE`, `VALID_START`), and
`drivers/vin/vin-isp/isp600/isp600_reg_cfg.c` and `drivers/vin/vin-isp/sunxi_isp.c`, which derive the
lossless group from the frame's width and bit depth.

## Checks

1. The C cross-check (done, host): the bit fields of the vendor header give `0x001f01f3` for a full
   expand, `0x000a00c2` and `0x000a00c1` for the two test values, `0x01000040` for black level and
   AE in `MODULE_BYPASS1`, `0x3f07ffff` for every named module, and `0x00080000` for reserved bit 19.
   The register offsets (`0x120`, `0x124`, `0x128`, `0x380` to `0x394`, `0x1b8`, `0x134`, `0x320`) match.
   Host run only: the script lives under the gates' tmp directory.
2. Endianness: the register words are read by the block little-endian. Confirm once with a known
   expand value: read the loaded image back through the vendor's register dump and compare.
3. Black level and bit depths take effect. Load an image with `ChannelExpand { black_level: true,
   input_bits: 12, output_bits: 10 }` on channel 1 and check the captured frame's levels. The kernel
   also writes these registers directly from its own sensor setup (`bsp_isp_set_ch_input_bit`), so
   check which value the block uses after a load: the image's or the kernel's.
4. Module enables. Set `BLC` and `WB` only, load, and confirm the captured frame changes as expected
   against the same frame with the vendor's setting.
5. Temporal denoise record enable. Turn `set_temporal_record(true)` on and run a stream of frames: the
   block must write its records into the kernel's temporal denoise buffers only, with no fault.
6. Extent words. The check refuses any nonzero input size, valid size, valid start or lossless word.
   Two things to confirm on the board:
   - A zero lossless group must not stop the block's lossless path. If the kernel fills these words
     itself into the image, the zeros are replaced at load. If it does not, the block runs without
     its extents: record which, and whether the frame is correct. A failure here is the first thing
     to report, and the driver must then get these values from the kernel's own state. That change is
     not in this PR.
   - The kernel's own values for these words, read back from the block's registers after a load,
     must equal the values the kernel computes from the frame size (`isp600_reg_cfg.c`).
7. Refusal. A job whose image has a nonzero address or extent word is dropped before the kernel sees it.
   Confirm the kernel log shows no ioctl and the job reports the refusal.

## Not checked here

Every block without a public encoding (white balance, colour matrix, gamma, tone, lens shading, spatial
denoise, sharpen, statistics decode) is not encoded and has no check. See `docs/drivers.md`, "ISP600 tuning".
