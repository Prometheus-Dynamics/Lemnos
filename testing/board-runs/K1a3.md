# K1a3 board run: VEPU541 H.265 encoder on the CM5

Status: untested on board. The layouts are checked against gcc and clang (every register, field
and address register), and the builder and the played kernel's `Block::Rkvenc` are covered by
`drivers/rkvenc/tests/builder_h265.rs` and `drivers/rkvenc/tests/codec_block_h265.rs`. No real encode
has run on the hardware.

Setup: a CM5 (Raze #2) with the VEPU541 encoder present on the rkvenc block. Take the board lock
named in `AGENTS.md` (`/run/lock/board-gpu.lock`) before starting. Build on the NVMe or SSD, never on
the HDD. Report CM5 timings only.

Facts the run checks against (from the header, see `drivers/rkvenc/src/vepu541_h265/mod.rs`):

- Identity word: word 0, `version`, field `RKVENC_VER`, default `0x1`.
- Read-back: words 7 to 208 (`READ_BACK`), word 7 `hw_status`, word 132 `st_bsl` (the stream length).
  Word 0 is outside the read-back window, so the identity word is read by a separate read, if the
  block offers one; this run does not assume it does.
- Second window: word 1 of the L2 window (`LVL32_INTRA_CST_THD0`, bits 0 to 11, and
  `LVL32_INTRA_CST_THD1`, bits 16 to 27) at `L2_FIRST` (0x4000). The L2 words are write-only here:
  the read-back does not cover them.

Steps:

1. Bind the driver and claim the rkvenc block. Pass: the claim succeeds.
2. Identity: read word 0 by the separate read above. Pass: `RKVENC_VER` reads `0x1`. If the block
   offers no separate read of word 0, record that and skip this step.
3. Read-back with no encode: run a job that writes nothing and reads words 7 to 208. Pass: the job
   completes with 202 registers and `hw_status` (word 7) reads 0.
4. One encode: a single intra picture from a caller-supplied source buffer (`ADR_SRCY_HEVC`, word 70)
   and a reconstruction buffer (`ROI_ADDR_HEVC`, word 73, offset 1024), with the stream buffer as
   the codec.block stream reference. The caller sets every other value. Pass: the job completes,
   `ENC_DONE_STA` (word 7, bit 0) is set, `BS_LGTH` (word 132) is non-zero and the stream buffer holds
   a bitstream that begins with the caller's parameter sets.
5. L2 words: rerun step 4 with `LVL32_INTRA_CST_THD0` set to `0x123` and `LVL32_INTRA_CST_THD1` to
   `0x456`. Pass: the job completes with the same result. The L2 words cannot be read back, so this
   step proves only that the second window's run is accepted; no value is confirmed on the board.

Record the outputs in this file under the step numbers, with the kernel's `dmesg` lines for any
failure. A failed step is written as it happened, not as a pass.
