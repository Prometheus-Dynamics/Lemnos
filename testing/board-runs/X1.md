# X1 board run: the self-test contract on the reference board

Status: untested on board.

The contract is checked on the simulator and through the bridge (`docs/drivers.md`, "Self-tests").
These checks run it on the reference board's own devices. None of them moves a device the board
needs for anything else. Run them in a local session that holds `/run/lock/board-gpu.lock`, on the CM5
only (`docs/testing.md`), with the board's services that use the fan or the indicator stopped first.

1. Read-only tests first: `lemnos-ctl call <device> tests` on the magnetometer (`bmm150`) and the power
   monitor (`ina2xx`), then `lemnos-ctl call <device> run identity false` and
   `lemnos-ctl call <device> run bus_voltage false`. Expect `pass` for the magnetometer's
   `identity` (chip ID `0x32`), and for the power monitor a `pass` only when the board file's
   `self_test_bus_min_mv` and `self_test_bus_max_mv` bracket the bus voltage the board reports.
   Without those keys the answer must be `skipped` with reason `NOT_CONFIGURED`. Record the bus
   voltage the board reads and the time each run takes against `expect_ms`.
2. The watchdog, read only: `lemnos-ctl call <watchdog> run answers false`. Expect `pass` with the
   timeout the board's watchdog reports, and check that its feed timing did not change (the
   `lemnos-ctl list` `timeout` value is the same before and after).
3. The fan, intrusive, with the fan free to spin and nothing else using it: stop `fan-control`, then
   `lemnos-ctl call <fan> run spin false`. Expect the fan to turn for about 3 s, the record to say
   `pass` within `self_test_rpm_min` and `self_test_rpm_max`, and `pwm1` and `pwm1_enable` to read
   back the values they had before (`cat` both before and after). Then start `fan-control` again.
   Repeat with `lemnos-ctl call <fan> run spin false` while another client holds the fan
   (`lemnos-ctl call <fan> duty 300`), expect `BUSY`. Record the reading and the tachometer's range.
4. Cancel: start `spin` again and cancel it after one second (Ctrl-C on `lemnos-ctl call`). Expect the
   fan's `pwm1` and `pwm1_enable` back at their earlier values at once, with no further write.
5. The indicator, intrusive, with an operator watching the LEDs: `lemnos-ctl call <indicator> run lamp false`
   must answer `skipped` with reason `NEEDS_OPERATOR` and change nothing. Then with `true`, and the
   operator reports the `receiving` state for about 2 s, then the state the indicator had before.
6. The board's own run, with the members above: `lemnos-ctl call selftest run all false`. Expect
   the overall record with the counts of each outcome, and `tests` listing `member:test` names in board
   order. Record the total time against the sum of the `expect_ms` bounds.

Record each reply, its time, and the bus voltage, the tachometer reading, and the fan's registers
before and after, here. Anything that differs from the expectation above is a finding.
