# E18 board run: the Rockchip JPEG decoder and encoder

Status: untested on board. The layouts and numbers, the address placement checks, the read-back
decoding and the session's reopen and backoff have passed their tests
(`drivers/rk-jpeg/src/layout_tests.rs`, `drivers/rk-jpeg/src/tests.rs`). Nothing has run on a
block. No job path exists yet: the registers that fix how far each block reads and writes are not
named in the vendor kernel's source, and the `/dev/mpp_service` call needs a safe wrapper not on
`next` (it belongs in `drivers/rk-mpp`, E16). Everything was read from rockchip-linux/kernel
`develop-6.1` at `77168c8d5ab82399f65a80e9f807b50ba37cf483`: `include/uapi/linux/rk-mpp.h`,
`drivers/video/rockchip/mpp/{mpp_jpgdec.c,mpp_jpgenc.c,mpp_common.c,mpp_common.h}`.

Boards: RK3588 or RK3568 for the v1 decoder (`rockchip,rkv-jpeg-decoder-v1`), RK3576 for the v1
decoder and the v1 encoder, RK3538 for the v2 decoder. Vendor kernel, `mpp_service` bound. Take
`/run/lock/board-gpu.lock`. Build on NVMe or SSD, never on the Github HDD. Module loads, unbinds
and rebinds are allowed; report each.

## Checks once a service `Device` exists

1. **Binding and ids.** `Jpeg::new(Variant::from_compatible(<the node's compatible>), …)` then
   `hw_id`. Record the id for each block. Pass: the decoder v1 on RK3588 answers a value whose
   high half is `0xdb1f` (record whether it is `0xdb1f0006`), and binding the encoder on a board
   without one is `EINVAL` and backs off.
2. **Register file sizes.** Read back the whole file through `read_window(variant, 0,
   variant.registers())` in a job of zero work (local test only). Pass: the call is accepted and
   register 0 holds the id from check 1. Then a window one register past the end must be refused
   by `read_window` before reaching the kernel (it is, in the tests); record what the kernel does
   with a hand-made one (local test only), to confirm its miscomputed clamp.
3. **Offsets.** With `FLAG_REG_NO_OFFSET` and an offset list, place the decoder's stream register
   (12) at offset 4096 in a buffer and read register 12 back after a job. Pass: the stream the
   block consumed (`status::decoded_bytes`) counts from that offset.
4. **What the registers do not say.** For each block, record from the TRM (not the vendor
   library) which registers fix the picture size, strides, formats, the stream length (decoder),
   the bitstream window and ECS length buffer size (encoder), and whether link mode can be held off
   by a register the kernel does not reset. These are what a checked job needs.
5. **Recovery.** While `hw_id` runs in a loop, unbind the block's platform device, wait 20 s, bind
   it again. Report both. Pass: `Device`, then `BackingOff` with delays 250 ms doubling to 8 s;
   after the bind the next due call opens and binds again.
