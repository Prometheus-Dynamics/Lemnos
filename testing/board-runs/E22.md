# E22 board run: k230-gsdma

Status: untested on board. The crate carries the engine's registers and 24-byte descriptor
(pinned against gcc and clang for riscv64 and riscv32), jobs checked against the dma-bufs a caller
holds, the descriptor chain a plan makes, and a claim over a small `Device` trait. The SDK's
kernel driver gives user space no node, request or mapping (it only exports
`canaan_gdma_rotate_sync` to the display driver), and the engine has no MMU, so driving its
registers from user space cannot be made safe. Since H7b the `Device` on Linux goes through
`lemnos.ko` instead; its board check is `H7b.md`. These checks still confirm the facts both rely
on.

Run in a local session on a K230 board running the K230 Linux SDK kernel
(`ruyisdk/linux-xuantie-kernel` at `7d4e1f444f461dbe3833bd99a4640e7b6c2cd529`, with the patches
`kendryte/k230_linux_sdk` at `fc6cc21` applies). The CM5 has no such block. Build on NVMe or SSD,
never on the Github HDD. Module loads and unbinds are allowed; report each. Never write the
engine's registers from user space (no `/dev/mem`, no `devmem` writes): the engine reaches all of
memory.

## Checks

These confirm the facts the crate pins, so that a kernel interface and a `Device` can be written
on them.

1. **The node.** `ls /sys/firmware/devicetree/base/soc/ | grep gdma`; read its `reg` (expect
   `0x80800000`, size `0x1000`), `interrupts` (expect 140) and `power-domains` (the VPU domain).
   `grep -i gdma /proc/interrupts`; `cat /proc/iomem | grep 80800000`;
   `ls /sys/bus/platform/drivers/ | grep -i gdma`. Record the kernel version.
2. **No user interface.** `ls /dev | grep -i dma`; `ls /sys/class/misc`. Pass: no node belongs to
   the engine. If one does, record its name and stop: the crate's premise has changed.
3. **The registers at rest.** As root, read only (`devmem 0x80800000 32` and the same for offsets
   `0x04`, `0x08`, `0x0c`, `0x48`): channel 0's enable, interrupt mask, status, config and weight.
   Record each. With the display rotating a plane (any demo that sets `rotation` on a DRM plane),
   read `0x0c` and `0x48` again: they should be `0x7ff` and `0x444210`, the values the crate pins.
4. **A rotation through the display.** With the same demo, turn a plane by 90 degrees and confirm
   `dmesg` shows no GDMA timeout (`gdma` messages). This exercises the engine through the only
   path the kernel offers; it does not exercise this crate.

Record each result here.
