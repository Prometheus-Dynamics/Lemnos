# E19 board run: A733 video engine (`/dev/cedar_dev_ve2`)

Status: untested on board. The uAPI structures and request numbers are pinned against gcc
(x86_64) and clang (aarch64) on the Radxa `allwinner-bsp` header at commit
`a842bb8dc74608ba13975c97c31b9518f1976c01`. The claim, buffer, address, register-window and
backoff logic has passed its tests over a played-back device and real memfds. No request has
reached an engine: this PR has no Linux `Device` (no safe public request for this node exists in
`lemnos-linux-sys`; see the crate docs), so the checks below that need one wait for it.

Run in a local session after the missing piece lands, on an A733 board running the Radxa BSP
kernel with `/dev/cedar_dev_ve2` present. Build on NVMe or SSD, never on the Github HDD. Module
loads and unbinds are allowed; report each.

## Checks

1. **The node and the window.** `ls -l /dev/cedar_dev_ve2`; `dmesg | grep -i -e cedar -e ve2`;
   record the kernel version. From the live device tree, confirm the window and offset the crate
   assumes: `xxd /proc/device-tree/soc@3000000/ve2@1c10000/reg` (pass: first entry
   `0x01c10000`, size `0x1000`) and `.../ve_top_reg_offset` (pass: `0x800`), and that the node
   has `iommus` (pass: present). If the window differs, `uapi::WINDOW_BYTES` is wrong: stop.
2. **Claim and release.** With a Linux `Device`, claim with `Lock::Encoder`, read
   `uapi::TOP_REG_OFFSET` and `uapi::ENC_INT_STATUS`, release. Pass: the reads return without a
   bus fault and `cat /sys/kernel/debug/ve/ve_dvfs2` (if debugfs is mounted) or the clock tree
   shows the engine's clock on while claimed and off after release. Run it 100 times; the clock
   must end off.
3. **A second claimant waits.** Claim from two processes. Pass: the second blocks in the claim
   until the first releases or exits, then gets it. Record that a process killed while claimed
   leaves the clock on (the kernel does not undo `IOCTL_ENGINE_REQ` on close).
4. **Bus addresses.** Attach dma-bufs from `/dev/dma_heap/system` of 4 KiB, 1 MiB and 64 MiB.
   Pass: each answers a nonzero bus address whose range ends below 2^32, and `dmesg` is clean of
   IOMMU faults. Attach the same buffer twice and detach both; pass: no warning. Attach a memfd;
   pass: refused, the engine stays claimed.
5. **Completion.** `Block::wait(Completion::Encoder, 1)` with no job queued. Pass: `Ok(false)`
   after about one second, still claimed. No job can be started from this crate (no register
   writes; see the crate docs), so a completing job is not part of this run.
6. **Recovery.** While claims run in a loop, unload the module or unbind the device (report
   which), wait 20 s, then load or bind it again. Pass: calls answer `Device` and then
   `BackingOff`, with delays from 250 ms doubling to 8 s and holding there; once the node is back
   the next due claim succeeds.
