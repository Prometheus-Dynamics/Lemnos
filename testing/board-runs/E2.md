# E2 board run: the 2D block (rga)

Status: untested on board. On a PC the routes' logic has passed its tests: the V4L2 route against a
mock node (`drivers/rga/src/v4l2/tests.rs`), the multi-RGA requests against memfd buffers that are
built and checked but never sent (`drivers/rga-sys/src/request.rs`, `drivers/rga/src/multirga/device.rs`),
and the CPU route with its RVV rows under qemu user mode at VLEN 128, 256 and 512 and with V off
(`drivers/rga/rvv-qemu.sh`). No request has reached an RGA unit. The multi-RGA field mappings were
read from the vendor kernel's uAPI header, not from a running board.

Run in a local session after this PR merges. The mainline checks need a Rockchip board on a
mainline kernel with `rockchip-rga` bound (RK3568 or RK3588). The multi-RGA checks need an RK3588
board on the vendor kernel (`develop-6.1`) with `/dev/rga` and `/dev/dma_heap/system`. The RVV
check needs the K230 (C908 core, VLEN 128). Build on NVMe or SSD, never on the Github HDD. Module
loads, unbinds and rebinds are allowed; report each.

## Checks

1. **Mainline route against the references.** With `rockchip-rga` bound:
   `LEMNOS_TEST_DEVICES=1 cargo test -p lemnos-driver-rga --test v4l2 -- --nocapture`. Pass: every
   `rga_*` test passes, conversions and crops exact, resizes within one level, and the printed
   differences are recorded here. With `vim2m` loaded (`modprobe vim2m`) on any machine, the
   `vim2m_*` tests pass too, including `vim2m_blits_between_dmabufs`.

2. **Multi-RGA field mappings.** On the vendor kernel:
   `LEMNOS_TEST_DEVICES=1 cargo test -p lemnos-driver-rga --test multirga -- --nocapture`. Every
   mapping is marked unverified in `drivers/rga/src/multirga/device.rs`. Record, per test: fill (the
   colour's byte order, and that the active rectangle is the fill area), mask ROP (that 0x88, 0xee,
   0xf6 are AND, OR, XOR and `dst` is both operand and target), blend (the Porter-Duff values and
   the premultiplied flag), colour key (whether the range alone keys, with no enable bit), gray to
   RGBA, the flips and turns (which mirror is horizontal, which way a quarter turn goes).

3. **Zeroed fields stay inert.** The request sends zero in every address field but `yrgb_addr` (the
   dma-buf fd), zero in `mmu_info`, and no pattern or LUT. Turn on the vendor driver's debug output
   (find its switch in its debugfs or module parameters; the name was not checked) and confirm
   each job is taken as a dma-buf import, that the MMU is not enabled for it, and that a ROP job
   does not read the pattern channel. A job that the kernel takes as a virtual or physical address
   is a failure: stop and report it.

4. **dma-buf contiguity.** Buffers from `/dev/dma_heap/system` are not contiguous. Check whether the
   kernel accepts them for each core (RGA3 and RGA2 have IOMMUs on RK3588; an RGA2 core limited to
   4 GB is a known constraint). Record any job refused, and its core.

5. **`channel_to_gray` is exact.** `a_channel_to_gray_is_exact_for_every_byte` passes for R, G and B.
   Until it does, `caps` does not route the operation to the unit.

6. **RVV on the real core.** On the K230: `LEMNOS_EXPECT_VECTOR=1 cargo test -p lemnos-driver-rga
   --lib cpu::` and `cargo test -p lemnos-driver-rga-sys --lib rvv::`. Pass: both green, and the
   vector path was taken (the `LEMNOS_EXPECT_VECTOR` test passes). The path is chosen at run time
   from `AT_HWCAP`, so this is the only check that the rows run on silicon and not only in qemu.

## Job streams (E2b)

E2b made the driver serve its three job streams (`scale`, `convert`, `blend` in the board file).
On a PC they are tested through the host's own stream (`drivers/rga/src/serve/tests.rs`,
`drivers/rga/tests/stream.rs`): the CPU route end to end with real pixels on streams with and
without handles; the mainline route on the played-back node with the stream's handles (sealed
memfds) and with bytes; the `/dev/rga` route on a stand-in that checks and records each request;
a failed unit's jobs falling to the CPU with retries at 250 ms doubling to 8 s; and no allocation
in steady state on each of those. No job has reached a unit.

7. **Jobs through lemnosd on the mainline route.** On the RK3588 mainline kernel, a board file
   with the `rga` device, `config = { soc = "rk3588" }` and `[devices.streams.scale]` (4 buffers
   of 1920x1080x4 bytes, `job_bytes = 64`) whose memory is `dma-buf`. A consumer posts a 2x area
   downscale of an AR24 1920x1080 frame. Pass: the completion carries 960x540x4 bytes, the
   output is within one level of the CPU route's (run the same job with no `soc`), and the
   kernel's debug output (or `strace -e ioctl` on lemnosd) shows `VIDIOC_QBUF` with
   `V4L2_MEMORY_DMABUF`. Then the same with the stream's memory plain: `V4L2_MEMORY_MMAP`, and
   the same result.

8. **Blend and gray input through `/dev/rga`.** On the RK3588 vendor kernel, `soc = "rk3588"`,
   `[devices.streams.blend]` and `[devices.streams.convert]` with `dma-buf` memory. Post a
   source-over blend of two premultiplied AR24 frames and a packed GREY to AR24 conversion.
   Pass: each output matches the CPU route's within the tolerance check 2 records for the blend
   and exactly for gray; the blend is two requests (a plain copy of the background, then the
   blend). Record whether the premultiplied flag's encoding (unverified) gave the CPU's result.

9. **A unit that goes away.** While jobs run on the mainline route, unbind `rockchip-rga`
   (`echo <dev> > /sys/bus/platform/drivers/rockchip-rga/unbind`). Pass: every job still
   completes (on the CPU, same result), health reads degraded, and the node is looked for again at
   250 ms, 500 ms, ... up to every 8 s; after binding it again the next due attempt takes the jobs
   back and health is ok. Report the unbind and rebind.
