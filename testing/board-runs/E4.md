# E4 board run: g2d

Status: untested on board. The request layouts are pinned against the C compiler's sizes and
offsets, and every check that stands between a caller and the engine (frame against dma-buf size,
rectangle against frame, the 32-bit frame cap, the signed position) has passed its tests on
memfds. No request has reached an engine, on dev or here.

Run in a local session after this PR merges, on an A733 board (the BSP's `g2d_rcq` engine)
running the Radxa BSP kernel (`allwinner-bsp`, the tree the structures were read from), with
`/dev/g2d` present. The CM5 has no G2D. Build on NVMe or SSD, never on the Github HDD. Module loads
and unbinds are allowed; report each.

## Checks

1. **The node answers.** `ls -l /dev/g2d /dev/dma_heap/`; `dmesg | grep -i g2d`. Record the
   kernel version and the heaps present.
2. **Every kind of job.** As root (or with access to the node and the heap):

   ```sh
   LEMNOS_G2D_NODE=/dev/g2d LEMNOS_G2D_HEAP=/dev/dma_heap/system \
     cargo test --release -p lemnos-driver-g2d --test board -- --ignored --nocapture
   ```

   Pass: the test passes: a uniform fill, a part fill that leaves the rest alone, a same-size copy
   byte for byte, a half-size scale that stays inside its rectangle, a quarter turn whose every
   pixel lands where one direction or the other puts it, and an opaque SrcOver blend equal to its
   foreground. Record what it prints: the engine and chip versions, the fill colour's bytes for
   `0x80402010` (unverified from the sources), and which way `Turn::Cw90` turned. If the heap is
   not `system`, try `linux,cma` and record which one the engine takes. Run it three times.
3. **NV12 chroma order.** Convert a 64x32 NV12 frame whose chroma is U=0x40, V=0xc0 to RGBA8888
   with `Job::blit` (a few lines over `Surface::new` and `G2d::run`, as the board test does).
   With Y=0x80, pass: the output is red (high R, low G and B) with `PixelFormat::Nv12`; record it.
   If it comes out blue (high B, low R), the NV12 and NV21 values are swapped.
4. **The kernel refuses what the checks refuse.** Not needed for safety (nothing out of bounds can
   be built), but record what `dmesg` says, if anything, through checks 2 and 3: it must be clean
   of g2d errors and IOMMU faults.
5. **Recovery.** While jobs run in a loop (a small program over `G2d` and `node("/dev/g2d")`),
   unload the g2d module or unbind the device (report which), wait 20 s, and load or bind it
   again. Pass: `run` answers `Device` and then `BackingOff`, with delays of 250 ms doubling to 8 s
   and holding there; after it is back, the next due call reopens and jobs pass again. Nothing
   panics and the engine never stops trying.

Record each result here.

## The driver (`G2dDriver`, E4b)

Added after the library: the `#[driver]` type `g2d` providing `image.convert/1` over `Converter`,
its jobs on the device's `jobs` stream. Untested on board: it is tested on the host's real frame
stream with sealed memfds for the dma-bufs and a counting engine (`drivers/g2d/tests/driver.rs`).
It needs `lemnosd` to list it (`scripts/generate-builtins.py`, a maintainer step) before these
checks can run.

6. **Through the daemon.** A board file with the device and its stream as the crate docs show
   (`memory = "dma-buf"`, from the `system` heap, then `linux,cma`). Attach a consumer to `jobs`,
   fill buffer 0 with a 64x64 ARGB8888 pattern, post an `image.convert/1` job to buffer 1 as
   XRGB8888. Pass: one completion on buffer 1 with the job's identity and 16384 bytes, the pixels
   equal with the alpha byte ignored, `counters` 1 job and 0 errors, health `Ok`. Then 1000 such
   jobs: record the median job time and the daemon's allocation counter (if built with it).
7. **The refusal.** The same board with the stream's `memory` left out. Pass: after a consumer
   attaches, the device's health is `Failed` with the text naming `memory = "dma-buf"`, and a job
   is counted as an error.
8. **Recovery through the daemon.** While jobs run, unbind and rebind the g2d device as in check
   5. Pass: jobs complete as failed (0 bytes) while it is gone, health is `Degraded`, and jobs pass
   again after the bind with no restart of the daemon.
