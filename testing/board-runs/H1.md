# H1 board run: the K230 ISP's registers mapped through `unconfined=`

Status: untested on board. What landed: the kernel module gained `unconfined=`: compatibles
whose registers it maps though no IOMMU confines their DMA, reported with
`LEMNOS_INFO_MMIO_UNCONFINED`. Its mapping of an `unconfined=` block passes in QEMU. Nothing of
this has reached a K230.

H1 also had `k230isp` and `k230-capture` take the ISP's register window and interrupt from the
host (`regs:`, `irq:`, `clocks:`, `resets:` under `uses`). H8b replaced that: both now reach the
ISP through the module's register jobs (`k230_isp=`), `k230-capture` in the frames role and
`k230isp` in the configuration role, on the same ISP at once. Their module-way checks are
`H8b.md`'s 9 to 11; the checks below are only of `unconfined=` itself.

Run in a local session after this PR merges, on a K230 board running the SDK's kernel
(`k230_linux_sdk` at `fc6cc21`), with `isp_media_server` not running. Build on NVMe or SSD, never
on the Github HDD. Module loads, unbinds and reboots are allowed; report each.

## Before anything

1. Find the ISP's platform device and what its firmware description gives it:
   `ls /sys/bus/platform/devices | grep -i isp`, then for that device `cat of_node/compatible`,
   `xxd of_node/reg`, `xxd of_node/interrupts`, `cat of_node/clock-names`,
   `cat of_node/reset-names`. Record each. Pass: one ISP device whose `reg` is at
   `0x90000000` with `0x9000` bytes or more (the ISP8000's window).
2. Which interrupt is which. The vendor's handler takes the ISP core's (`ISP_MIS`) and the memory
   interface's (`MIV2_MIS`) causes. Record how many interrupts the node lists. If it lists one,
   both causes come on the same line; if two or more, read the vendor driver's
   `platform_get_irq` calls (`buildroot-overlay/package/vvcam/isp/`) and record which index is
   which.

## Binding the ISP to the module

3. Unbind the ISP from `vvcam-isp`, load the module owning it with its registers mappable though
   unconfined, and bind it:
   `insmod lemnos.ko owned=<vendor>,<isp> unconfined=<vendor>,<isp>`, then the override and bind
   as `docs/kernel-module.md` says. Pass: `dmesg` shows `unconfined: registers mappable` and the
   block line ends `registers mappable (unconfined)`.
4. `lemnos-module-check board` (or a small program over `LinuxBoard`) opens `regs:<isp>`,
   `irq:<isp>/<n>` and, with the names from step 1, `clocks:<isp>/<names>` and
   `resets:<isp>/<names>`. Pass: each opens; `ModuleRegisters::unconfined()` is `true`; with the
   clocks on, word `0x5C4` (`ISP_MIS`) and `0x16D0` (`MIV2_MIS`) read without a bus fault.

## Afterwards

5. Unbind the ISP from the module, clear the override, rebind `vvcam-isp`. Pass: the vendor's way
   (E11, E30) still works after the module had the block.
