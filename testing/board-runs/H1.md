# H1 board run: the K230 ISP through the kernel module (`regs:`, `irq:`, `clocks:`, `resets:`)

Status: untested on board. What landed: `k230isp` and `k230-capture` each take the ISP's register
window and interrupt (and optionally its clocks and reset lines) from the host when the board file
names them under `uses` (`regs`, `irq`, `clocks`, `resets`), and the vendor's `vvcam-isp` node
otherwise. The kernel module gained `unconfined=`: compatibles whose registers it maps though no
IOMMU confines their DMA, reported with `LEMNOS_INFO_MMIO_UNCONFINED`. Both drivers pass their
tests against the simulated board's mocks, and the module's mapping of an `unconfined=` block
passes in QEMU. Nothing of this has reached a K230.

Run in a local session after this PR merges, on a K230 board running the SDK's kernel
(`k230_linux_sdk` at `fc6cc21`), with `isp_media_server` not running. Build on NVMe or SSD, never
on the Github HDD. Module loads, unbinds and reboots are allowed; report each.

## Before anything

1. Find the ISP's platform device and what its firmware description gives it:
   `ls /sys/bus/platform/devices | grep -i isp`, then for that device `cat of_node/compatible`,
   `xxd of_node/reg`, `xxd of_node/interrupts`, `cat of_node/clock-names`,
   `cat of_node/reset-names`. Record each. Pass: one ISP device whose `reg` is at
   `0x90000000` with `0x9000` bytes or more (the ISP8000's window).
2. Which interrupt is which. The vendor's handler takes the ISP core's (`ISP_MIS`) and the memory
   interface's (`MIV2_MIS`) causes. Record how many interrupts the node lists. If it lists one,
   both drivers' interrupts are the same line; if two or more, read the vendor driver's
   `platform_get_irq` calls (`buildroot-overlay/package/vvcam/isp/`) and record which index is
   which.

## Binding the ISP to the module

3. Unbind the ISP from `vvcam-isp`, load the module owning it with its registers mappable though
   unconfined, and bind it:
   `insmod lemnos.ko owned=<vendor>,<isp> unconfined=<vendor>,<isp>`, then the override and bind
   as `docs/kernel-module.md` says. Pass: `dmesg` shows `unconfined: registers mappable` and the
   block line ends `registers mappable (unconfined)`.
4. `lemnos-module-check board` (or a small program over `LinuxBoard`) opens `regs:<isp>`,
   `irq:<isp>/<n>` and, with the names from step 1, `clocks:<isp>/<names>` and
   `resets:<isp>/<names>`. Pass: each opens; `ModuleRegisters::unconfined()` is `true`; with the
   clocks on, word `0x5C4` (`ISP_MIS`) and `0x16D0` (`MIV2_MIS`) read without a bus fault.

## `k230-capture` on the module's way

Board entry: `uses = { regs = "regs:<isp>", irq = "irq:<isp>/<n>", dma = "dma:<isp>", clocks =
"clocks:<isp>/<names>", resets = "resets:<isp>/<names>" }`, no `isp` in `config`.

5. Bind and start a raw 10-bit capture from the attached sensor, as E30's step 4 does. Pass: the
   device runs, frame ends arrive (each `MIV2_MIS` read carries bit 0 or 1, and is cleared: the
   interrupt does not fire again until the next frame end), and `active` names memories 1, 2, 0,
   1, ... in turn. Record whether the interrupt line also carries the ISP core's causes.
6. E30's step 3 (guard memory around the ring) on this way, with the ring from `dma:<isp>`. Pass:
   every guard byte still reads `0xA5`, both with the sensor at the configured size and one line
   taller. This is the check the `unconfined=` listing rests on: the module does not confine the
   block's DMA, the driver does.
7. Stop, kill `lemnosd` while streaming, start again. Pass: the next start resets the block
   (each reset line asserted, then released) and frames resume; `dmesg` shows nothing from the
   module but the claims released.

## `k230isp` on the module's way

Board entry: `uses = { regs = "regs:<isp>", irq = "irq:<isp>/<n>" }` (the ISP core's interrupt),
no `device` in `config`. `k230-capture` cannot hold the same window at the same time, so this runs
with the vendor's capture path stopped and the sensor streaming into the ISP.

8. E11's statistics steps on this way. Pass: a job's register list lands (read back through the
   table), its statistics arrive two frames later, and each frame-out interrupt is cleared through
   `ISP_ICR` (no interrupt storm: `/proc/interrupts` grows by one per frame).

## Afterwards

9. Unbind the ISP from the module, clear the override, rebind `vvcam-isp`. Pass: the vendor's way
   (E11, E30) still works after the module had the block.
