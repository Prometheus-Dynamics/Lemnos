# I5 board run: slots and restart on the CM5

Status: untested on board. The `system-slots` and `system-reboot` drivers have run only over
temporary directories standing in for the data and boot partitions, with a boot record that writes
down what it was told and a script standing in for `systemctl`. Nothing has written a real boot
partition, restarted a board or booted a slot this driver installed.

Run in a local session on the CM5 (Raze #2) running a slots image built by Atlas from its `dev`
branch (the boot chain: `slot-init` as the initramfs, `config.txt` including `default.txt`,
`tryboot.txt` including `trial.txt`). Take `/run/lock/board-gpu.lock` for the whole run. Build on
NVMe or SSD, never on the Github HDD. Restarts and slot changes are allowed; report each. Keep the
board's own update writer (`/usr/lib/board/slots`) stopped for the run: it and this driver write the
same files.

## Setup

1. On the laptop, build two slot bundles with Atlas (`<id>.slot.tar`) from two images that differ
   (two versions of one OS), with schema 3 manifests whose `board` is the board file's
   `[board] id` (`docs/slots.md` gives the keys and the `veritysetup` command). Build a third
   whose `board` is another board's. Sign each bundle's `slot.json` with the test key:
   `slot.sig` is the 64-byte Ed25519 signature over the manifest's exact bytes, added to the tar.
   Put the test key's public half in `/etc/lemnos/slot-keys` on the board as one line: 64 hex
   digits, a space, `board-run test key`.
2. A board file with:

   ```toml
   [[devices]]
   id = "slots"
   driver = "system-slots"
   config = { data = "/data", boot = "/boot/firmware", keys = "/etc/lemnos/slot-keys", boot_args = "atlas" }

   [[devices]]
   id = "reboot"
   driver = "system-reboot"
   ```

   `boot/firmware` must be the boot FAT, mounted read-write. Record `findmnt /data
   /boot/firmware` and `ls /dev/disk/by-partuuid`.
3. Start `lemnosd` with it. Pass: `lemnos-ctl list` shows both devices running.

## Checks

1. **List.** `lemnos-ctl call slots list`. Pass: the JSON names the running slot as `slot_active`
   and `slot_default`, the slot's `product`, `version` and `board` as `slots`'s first entry, and free space close
   to `df -B1 /data`.
2. **Install, streamed.** Send the first bundle in 1 MiB writes through the client
   (`install(size, false, false)`, then `write(offset, bytes)`), printing progress. Pass: progress
   rises to the size, the job ends with the new id, `/data/slots/<id>.erofs` matches the bundle's
   `rootfs.erofs` byte for byte, `/data/slots/<id>.boot` lists every boot file plus `slot.json`,
   and the kept `cmdline.txt` ends with `atlas.slot=<id> atlas.roothash=<hash>
   atlas.data=PARTUUID=<the data partition's> panic=5`. Compare that line with one the board's own
   writer produced for the same bundle; they must be equal.
3. **Refusals.** The same bundle with one byte of `rootfs.erofs` changed, then with `slot.sig`
   from another key, then cut short, then the bundle built for another board. Pass: each ends
   `-22`, `-1`, `-22`, `-95`; `/data/slots` holds no
   `.install.*` afterwards; `list` shows the reason as `error`. Then restart `lemnosd` with
   the security switch off (`docs/slots.md`) and install the bundle signed by the other key. Pass: it installs and
   `list` shows it `"signed":"untrusted"`; the first bundle shows `"trusted"` with
   `"signer":"board-run test key"`. Put the security switch back on.
4. **Cancel and kill.** Start an install, cancel it at about half; start another and kill the
   client at about half; start a third and restart `lemnosd` at about half. Pass: each leaves no
   work behind; the restarted service's `list` says the install was interrupted.
5. **Trial, confirmed.** `trial(<id>, false, false, false)`. Pass: the board restarts once into the
   new slot (`cat /proc/device-tree/chosen/bootloader/tryboot` reads 1, `/data/board/slots/booted`
   names it). Then `confirm`. Pass: `default.txt` names it, the FAT's root `kernel_2712.img` is its
   kernel, `list` shows the old slot as `previous`.
6. **Trial, not confirmed, single slot.** Remove every slot but the running one (pin nothing).
   Install the second bundle and trial it; when it is up, do not confirm: `lemnos-ctl call reboot
   reboot`. Pass: the board comes back on the default slot; `confirm` records the trial as failed
   (`good` `no`, `failed` true) and `previous` stays empty.
7. **Housekeeping.** `set_keep 1`, pin one slot, install and confirm two more. Pass: only the
   running, the pinned and the previous slot are left, and `slots/` on the FAT has only resident
   slots' directories.
8. **Install from a file.** `accept(<size>)`, then copy the second bundle into
   `/data/slots/.incoming/b.tar` as a member of group `lemnos` and call
   `install_file("b.tar", false, false)`, printing progress. Pass: `accept` answers 0 and,
   asked with `<free bytes>` as the size, `-28`; `ls -ld /data/slots/.incoming` shows
   `drwxrwx---` and group `lemnos`; the job ends with the id; the file is gone. Repeat with a
   symlink named `l.tar` pointing at the bundle: `-22`, and the bundle it points at is untouched.
   Cut the file short and install it: it ends `-22` and the file is gone.
9. **The U-Boot record.** Only on a board that boots U-Boot (not the CM5's firmware): build
   `packaging/uboot/boot.cmd` into `boot.scr` with `mkimage`, put it on the boot partition and
   set `record = "uboot"`. Install a slot, `cat /boot/slots/<id>/extlinux/extlinux.conf`, and trial
   it. Pass: on the U-Boot console the script disarms the record (`boot-record.env` reads
   `trial_armed=0` once the slot is up) and boots the trial; a restart without `confirm` boots
   the default; with `boot-record.env` removed it boots `/extlinux/extlinux.conf`. This is the
   script's first run anywhere.
10. **The board's writer reads it back.** Start the board's own `slots list` after the checks.
   Pass: it reports the same default, previous and per-slot state as this driver's `list`.

Record every restart and the output of each check.

## Note 2026-11-13 (I5g2): the signed message changed

The message a bundle's `slot.sig` signs is no longer the bare `slot.json` bytes. It is the domain-tagged
`lemnos-slot-bundle\0 | u32 LE 1 | u32 LE len | slot.json` (`lemnos_slot_store::signing::slot_bundle_message`).
The record container and the policy are unchanged. Bundles signed over the bare manifest (as this run's
bundle was) are refused under a held key. The section above describes the bundle as it was at I5g; it is
kept as the historical record. See `docs/slots.md`, "A bundle", for the current layout and vector.
