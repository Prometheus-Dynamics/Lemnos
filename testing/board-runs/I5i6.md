# I5i6: the firmware mailbox, the production boot count, `tree --boot-dir`, and lemnosd's raw boot-file check

Not run on a board. Every test named in the PR body runs on this PC: the mailbox crate's layout and
tag tests and a plain-file device, the count module over real state and history files in temporary
directories with a recording record, a fake mailbox and a fake device-tree directory (cut at every
step), and `lemnos-ctl tree --boot-dir` into a temporary directory. No board was touched.

## What a run does

For each point: the step, the expected result, and the result read, with the firmware version from
`vcgencmd version` and the image's build. A point that fails is recorded with its output; the check
is not turned off to make a run pass.

## Known gaps (recorded, not run)

- The state's error and the boot history's entry for an arrival are written; the indicator is not
  yet told (the arrival's report step has no indicator call).
- The board file has no `firmware` key. The firmware family is the `system-slots` device's
  `record = "tryboot"`, and `tree --boot-dir` keys off that.
- Board firmware lines are the `--boot` fragment (the `gpio=` holds); nothing else in the board file
  is a firmware line today.
- The lemnosd boot-file check finds the boot partition's node as slot-init does, from the boot
  chain's source and the board's `boot_sources`, and reads its files raw from that node; a node that
  cannot be found refuses the read by name.
- Other firmware kinds, and the U-Boot forms, are not in this PR.
