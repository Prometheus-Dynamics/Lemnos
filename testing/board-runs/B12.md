# B12: hwmon-fan

Status: untested on board. The hand-back is covered by unit tests over a fake sysfs tree (the
driver's `src/tests.rs`): release, drop, panic, missing and unwritable attributes, and the
`pwm-fan` cooling-device path. No real fan has been handed back.

Run on the CM5 with a real fan on a hwmon device, bound by the board file's `hwmon-fan` device. Give
the fan with `config = { name = "<hwmon name>" }`, or `config = { hwmon = "hwmonN" }`, taken from
`/sys/class/hwmon/*/name`. A second chip fan with an automatic mode is optional, for check 6. Take
the board lock named in `AGENTS.md` (`/run/lock/board-gpu.lock`) before starting, and build on NVMe
or SSD, not the HDD.

The driver is not yet in the host's driver registry, so the run waits for the PR that registers it.
Until then, drive the fan through a client as the other board runs do. Record the values from check
1 before any write. They are the expected values for every check after it.

1. Baseline. Record, before any write, the fan's `pwm1`, `pwm1_enable` and `fan1_input`, the
   fan's `device/driver` link, and for each cooling device its `type` and `cur_state`, plus the
   `policy` of each thermal zone bound to it.
   Pass: every value is written to the run notes, and nothing has changed them since.
2. Take the fan over: `set_duty(1000)`, then `set_duty(300)`.
   Pass: `pwm1_enable` reads 1 and `pwm1` reads 77 (300 per mille is raw 77). The fan slows from
   full speed, and `fan1_input` reflects that within a few seconds.
3. Read back with `duty` and `rpm` while the fan is taken over.
   Pass: `duty` reads 302 (raw 77 is 302 per mille) and `rpm` equals `fan1_input` at that moment.
4. Release: `release()` on the client.
   Pass: `pwm1`, `pwm1_enable` and each cooling device's `cur_state` equal the step 1 baseline. Each
   zone's `policy` file has a newer mtime, and the fan goes back to the speed the governor asks for.
5. Stop: take the fan over again with `set_duty(1000)`, then stop the service with `SIGTERM`.
   Pass: after the process exits, `pwm1`, `pwm1_enable` and `cur_state` equal the step 1 baseline.
6. Automatic-mode chip (optional): take a chip fan over with `set_duty(500)`, then stop the service
   with `SIGTERM`.
   Pass: the chip's `pwm1_enable` returns to the value recorded in step 1 (not a default), and
   `pwm1` returns to its recorded value.
7. Kill (documents the gap): take the fan over with `set_duty(1000)`, then `kill -9` the process.
   Pass: the fan keeps the last duty it was given (no code runs after `SIGKILL`). Restore it by hand
   from the step 1 baseline, and record that the run restored it by hand.
