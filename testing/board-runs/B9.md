# B9: bmm150

Status: untested on board. The register map, trim compensation, power-up sequence and the
retry-on-fault path are covered by the simulated-bus tests in `drivers/bmm150`. No transfer has
reached a BMM150.

## Setup

On the CM5, with a BMM150 wired to an I2C bus that the Linux I2C backend (B2) exposes,
and a board file that names the bus as `i2c-N` and the magnetometer as the `bmm150` driver. Take the
board lock from `AGENTS.md` before starting. Build on NVMe or SSD, never on the Github HDD. Report
CM5 timings only.

## Checks

1. Bind the driver at the chip's address (0x10 with SDO and CSB2 low) and read it twice in a row.
   Pass: the first read returns `AGAIN`, and the second returns three finite values in tesla.

2. Hold the sensor still and read it 20 times over two seconds.
   Pass: the field magnitude is between 25 µT and 65 µT (the Earth's field range), and no two
   consecutive readings differ by more than 1 µT.

3. Turn the sensor through a full turn in a horizontal plane while reading it.
   Pass: the horizontal components (x and y) keep a steady magnitude while their direction turns
   through a full circle.

4. Bring a magnet within a few centimetres of the chip, then take it away.
   Pass: the field changes by more than 100 µT while the magnet is close, and returns to the
   still-reading value once it is removed.

5. Set `preset = "high_accuracy"` and `data_rate = 2`, then read every half second.
   Pass: readings change at most every 500 ms, and a read that comes before a new conversion repeats
   the previous value.

6. Set `address` to 0x11 while the chip is at 0x10, then read.
   Pass: reads fail with `IO`, health reports `Failed("bus error")`, the host backs off with the
   retry delay capped at 8 s, and the device is not switched off.

7. With the correct address, disconnect the sensor's power for five seconds while reading, then
   reconnect it.
   Pass: reads fail while the sensor is absent, and after it returns the next read gives `AGAIN`
   and then valid values, with no restart of `lemnosd`.

8. Call read in a tight loop with no pause after the `AGAIN` from check 1, for 100 calls.
   Pass: any failure in the loop is followed by a valid read once the retry succeeds, and the
   process does not panic. Record the failure count and the read timings from the CM5.
