# E27 board run: a driver package on a CM5

Status: untested on board.

The loader's tests run on the build machine (x86-64), against the simulated bus. Not yet run: a
package on aarch64, and a package's driver on a real I2C bus.

1. Build lemnosd and `engine/package/tests/fixture` (`cargo build --release` in that directory)
   for aarch64, on the board or cross-compiled with the same toolchain and the same Lemnos tree.
2. Put `liblemnos_package_fixture.so` in a directory on the board. Start lemnosd with
   `--packages <dir> --package-mode open` and a board file with one device,
   `driver = "package-fixture"`, `uses = { bus = "<an I2C bus the board file names>" }`.
   Expect on its error output `package <path>: driver "package-fixture"`, and the device `running`
   in `lemnos-ctl list`.
3. `lemnos-ctl call <device> add 40 2` answers 42. `lemnos-ctl call <device> register <address>
   <register>` reads a register of a chip known to be on that bus (an identity register), and a
   read of an address with no chip fails without taking the device down.
4. `lemnos-ctl call <device> crash`: the call fails, the device shows `retrying (the driver
   panicked)`, and is `running` again about a second later. Other devices on the board are
   unaffected throughout.
5. Signed mode: make a key and sign the file as `docs/writing-a-driver.md` shows, start lemnosd
   with `--package-keys <file>` and no `--package-mode`, and expect the package to load. Append a
   byte to the `.so`, restart, and expect `refused: bad signature`.
6. A package built for x86-64 put in the directory is refused with `not a driver package: built
   for another kind of machine`, and nothing else changes.
7. Record here what was run and what each step showed.
