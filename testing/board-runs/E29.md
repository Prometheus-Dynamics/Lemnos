# E29 board run: a guest board on stock drivers

Status: untested on board.

The bench chain: a machine whose own kernel drivers own the hardware (the SystemCore unit), with
`testing/boards/guest.toml` as its board file. Every device in it is `owner = "host"`.

1. Check the board file's paths against the machine: `/sys/class/thermal/thermal_zone0/temp`
   exists, a hwmon device named `pwmfan` has `pwm1` and `pwm1_enable`, and
   `devices/system/clocksource/clocksource0/current_clocksource` is readable. Fix the config in the
   file if a path differs, and record the difference here.
2. Record `pwm1`, `pwm1_enable` and the fan's cooling-device `cur_state` before starting.
3. Start `lemnosd` with the board file. All three devices reach `Running`.
4. Reads work: the zone's temperature (method 1), the fan's duty (2) and rpm (3) answer, and the
   clock device's described values are listed.
5. Nothing is written: `set_duty` (1) and `release` (4) on the fan return `NOT_PERMITTED`, and so
   does any method the fan's description doesn't name.
6. Stop `lemnosd`. `pwm1_enable` and `cur_state` are as recorded in step 2, and `pwm1` moved only
   as the kernel's governor moved it. Optionally run with `inotifywait -m` (or `auditctl -w`) on
   the hwmon directory and confirm no write from the `lemnosd` process.
7. Add a device the stock drivers own with a driver that writes on its ticks (A34: `hw-watchdog`
   on `watchdog0`, `owner = "host"`). It never reaches `Running`, its reason names host
   ownership, and the watchdog's `timeleft` keeps counting down as before (nothing fed it).
   Remove the entry before leaving the machine running.
8. Not covered: the five CAN links (`net-link` has no driver on `next`).
