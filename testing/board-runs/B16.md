# B16: ws2812

Status: untested on board. The frame model, the SPI encoding, and the driver's bind, set, show,
failure and config paths are covered by unit and integration tests over the simulated SPI bus. No
frame has reached a real strip.

Run on the CM5 with a real WS2812 or SK6812 strip on an SPI bus, with the board file giving the bus
as `spidevB.C`, `count` set to the strip's LED count, `wire` (`"rgb"` or `"rgbw"`), and optionally
`offset`, `direction` and `brightness`. The bus must run at 2.4 MHz. Take the board lock named in
`AGENTS.md` before starting.

A frame is built with `set` and sent with `show`. `set` takes an LED index and up to 14 LEDs per
local call (`MAX_LOCAL_LEDS`). A frame of more than 14 LEDs is split across `set` calls, then one
`show` sends it.

1. Confirm the bus clock. Probe MOSI on the SPI bus while a frame is sent, and time one bit (a
   WS2812 data bit is three SPI bits).
   Pass: the SPI clock measures 2.4 MHz within 2%, and a data bit is 1.25 µs.
2. Read the pixel count through `lemnos-ctl` on the running `lemnosd`, with no `--sim`.
   Pass: the count matches the strip's LED count.
3. `set` a full red frame (`r=255 g=0 b=0 w=0` for every LED), then `show`.
   Pass: every LED is red and none flicker. Nothing changes on the strip before `show`.
4. `set` a single lit LED at index 0, with the board file's `offset` and `direction` set, then
   `show`.
   Pass: the lit LED is the physical index the config gives, and the rest are off.
5. Set `brightness` to 128 and show full white.
   Pass: the strip is visibly about half as bright as at 255, with no colour cast.
6. Show red and then blue frames back to back, 1000 times, and end on a known colour.
   Pass: the final colour is the last frame's colour on every LED, and no LED keeps an earlier frame
   (the 80 µs reset holds between frames).
7. For an RGBW strip (`wire = "rgbw"`), `set` a frame with only white set, then `show`.
   Pass: the white LEDs light with no red, green or blue.
8. Unbind the SPI device node while the driver runs, then restore it.
   Pass: `show` reports the failure, health reads `Failed` while the node is gone, and the next
   `show` after the node returns sends the same stored frame with no restart.
