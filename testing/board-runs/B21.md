# B21 board run: vcm (lens actuator) on a CM5

Status: untested on board. The chip layer and the driver are covered by unit tests on the
simulated bus (`backends/sim`). No write has reached a real DW9714, DW9807, DW9817 or AK7375.

Setup: one lens actuator wired to a CM5 I2C bus, with a board file device such as:

```toml
[[devices]]
id = "lens0"
driver = "vcm"
bus = "i2c-N"
config = { chip = "dw9817", address = 0x0c }
```

Optional keys: `min` and `max` (default `0` and the chip's highest position, 1023 for the DW9714,
DW9807 and DW9817, 4095 for the AK7375). They must lie within the chip's range. Use the entry for
the chip fitted.

The driver has no ID register to check, so a `chip` that does not match the actuator is not
detected. Check 8 covers this.

1. Build the driver for aarch64 and bind the device.
   Pass: bind succeeds. Health is `Degraded` (not powered) and `position` returns `NOT_SUPPORTED`.
2. Make the first move with `set_position(445)` on a DW9817.
   Pass: the call returns `AGAIN`, and the bus carries one write `0x02 0x00`. No move is written.
3. Make the second move, `set_position(445)`, on the same device.
   Pass: the bus carries `0x03 0x01 0xbd`, the lens moves, `position` returns 445, and health is `Ok`.
4. Move to 2000 with no range set.
   Pass: the bus carries `0x03 0x03 0xff` (clamped to 1023), and `position` returns 1023.
5. Set `min = 100` and `max = 600`, then move to 50 and then 700.
   Pass: the writes carry 100 and 600, and `position` returns 100 and 600 after each move.
6. Check the settle time with a DW9714 (12 ms power-up) and an AK7375 (10 ms).
   Pass: a move issued at least 12 ms (DW9714) or 10 ms (AK7375) after the `AGAIN` moves the lens
   to its position. Record whether a move issued sooner moves it. The driver never sleeps, so the
   gap is the host's.
7. Disconnect the chip's I2C wiring during moves, then reconnect it.
   Pass: moves fail with `IO`, and `position` keeps the last successful value. Health is
   `Degraded` (bus error) while disconnected. After reconnecting, the next call returns `AGAIN`,
   the call after it moves the lens, and no restart is needed.
8. Configure `chip = "ak7375"` against a DW9807, then move to 500.
   Pass: the move is written without an error, which shows the mismatch is not detected. Record
   where the lens goes. This check documents the limit, not a fault.
9. Point the device at an address nothing answers (for example 0x0d).
   Pass: bind succeeds and moves fail with `IO`. The driver keeps accepting moves and does not
   switch itself off. Retry pacing is the host's, and it stays within the 8 s cap.
10. Leave the lens at a position for 10 minutes after the last move.
    Pass: the position holds, and the driver never sends a standby write. The contract has no
    standby method, so the chip stays powered. Record the coil temperature at the end of the
    run if a probe is fitted.
11. Time 1000 moves to the same position on the CM5, and record the median and worst case here.
    Pass: every move is a single I2C write (one `write` per call), and the timings are recorded.
    CM5 timings only.
