# C3: I2C and SPI through the module, on a board

Run on the board 2026-11-11: I2C passed; SPI not run (no SPI device that may be touched).

On the CM5, A/B against `i2c-dev` and `spidev`, same bus, same target, same transfer shape:

1. I2C: a write-then-read of a register on a real device, many times, through `/dev/i2c-N` and through `LEMNOS_IOC_I2C_TRANSFER`. Same data both ways; record time per transfer.
2. SPI: full-duplex transfers on a real device or a jumpered MOSI to MISO, through `spidev` and through `LEMNOS_IOC_SPI_TRANSFER` with the device bound through `driver_override`. Same data; record time per transfer.
3. An address held by a kernel driver gets `EBUSY`.

## Result, 2026-11-11

Run 2026-11-11 on the CM5 (Raspberry Pi Compute Module 5 Rev 1.0, Raze #2), kernel `7.2.9-v8-16k`,
with `lemnos.ko`, `lemnosd` and the tools from PR F2a, built on NVMe and copied to
`/tmp/lemnos-run/` on the board. Raw logs are kept off the repository.

`lemnos-module-check board i2c=i2c-1:0x40:0x3f:2 held=i2c-10:0x60 line=gpiochip15:27
pwm=pwmchip0:0`, three rounds alternating stock and module (`insmod lemnos.ko` owning nothing).

1. I2C: register `0x3f` of the power monitor at `i2c-1` 0x40 (an INA238; it reads `[0x23, 0x81]`,
   the chip's id) read 2000 times each way, write of the register address then a 2-byte read. Same
   value every time on both routes, 0 allocations. Median / p99: stock about 505.4 / 524 µs, module
   about 505.6 / 525 µs. The bus clock was not read from the board; the time is the wire's.
2. SPI: not run. The board's only SPI device is `spidev10.0`, the boot EEPROM, and nothing is
   jumpered.
3. `i2c-10` 0x60, held by the kernel's sensor driver: a read is refused `Busy` on both routes.
