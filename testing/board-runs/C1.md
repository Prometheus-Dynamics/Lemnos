# C1: module core on a board

Run on the board 2026-11-11: passed after three fixes to the checks themselves (below). The QEMU
guest has no IOMMU and no real block.

On the CM5, with the stock driver unbound from a block whose registers are safe to leave alone:

1. `insmod lemnos.ko owned=<its compatible>`, set `driver_override`, bind.
2. `lemnos_check /dev/lemnos <device> /dev/dma_heap/linux,cma`: every line `ok`.
3. With `test_irq_inject=1 test_map_unconfined=1`: `lemnos_irq_check /dev/lemnos <device>`, every line `ok`; record the two latency lines.
4. With `confined=<its compatible>` and an IOMMU in front of the block: `info` reports the registers mappable.
5. Unbind with a buffer held: the writer waits, closing the buffer ends it, no splat in `dmesg`.

## Result, 2026-11-11

Run 2026-11-11 on the CM5 (Raspberry Pi Compute Module 5 Rev 1.0, Raze #2), kernel `7.2.9-v8-16k`,
with `lemnos.ko`, `lemnosd` and the tools from PR F2a, built on NVMe and copied to
`/tmp/lemnos-run/` on the board. Raw logs are kept off the repository.

The block was the PiSP back end, `1000880000.pisp_be` (`raspberrypi,pispbe`, behind an IOMMU,
36-bit DMA), taken from `pispbe` with the product's camera service stopped.

1. `insmod lemnos.ko owned=raspberrypi,pispbe test_irq_inject=1 test_map_unconfined=1`,
   `driver_override` `lemnos`, bind: `rc=0`, `block 1: 1 regions, 1 interrupts, 36-bit DMA,
   registers mappable`. Taint stayed 4096 (out-of-tree module only).
2. `lemnos_check`: first run 3 failed, all in the check. Two lines expected a refusal that
   `test_irq_inject=1` allows (the check now knows when injection is on), and the reopen failed with
   `EBUSY` because the check's own register mapping still held the node (it now unmaps first; QEMU
   never caught it because the registers there are not mappable). Rerun: 0 failed.
3. `lemnos_irq_check`: 0 failed. Injection to handler p50 0.5 µs, p99 0.5 µs, max 0.6 µs; to user
   space p50 1.5 µs, p99 1.5 µs, max 18.6 µs.
4. Loaded with `confined=raspberrypi,pispbe` (the IOMMU in front): `registers mappable`;
   `lemnos_check` 0 failed.
5. `lemnos_unbind_check`: 0 failed; no splat in `dmesg`.

`lemnos_stream_check` on the same block: first run 12 failed, every one an address check that
assumed a buffer's device address equals the address its dma-buf was made at. Behind an IOMMU each
attachment gets its own address. The check now compares what the stream maps, not the address;
rerun 0 failed.
