# I5i7: the U-Boot form's trial and default in U-Boot's own redundant environment, written raw

**Not run on a board.** Every test named in the PR body runs on this PC: `lemnos_slot_store::gpt`
(a GPT disk image), `lemnos_slot_store::uboot_env` over in-memory devices and disk images (the cut at
every byte of a write, sectors landing in any combination and torn over garbage, every serial value
with the wrap), the driver's `UbootEnv` record, slot-init's fallback on the `uboot` form, `tree
--uboot-config` and `--boot-dir`, and the script's text against the decision. U-Boot's sources at tag
`v2026.10` (commit `5508406582f6f7120dce0c4b3059819a41788db2`, read-only) are cited with file and line
in `drivers/slot-store/src/{uboot_env,gpt}.rs`, `packaging/uboot/boot.cmd`, `service/ctl/src/boot_dir.rs`
and `docs/slots.md`; each citation was checked against the file at that line, and each name in the
fragment was checked to be a `config` entry of that tree (below). No board was touched, and
`boot.cmd` was never run in a U-Boot: its logic is checked structurally, and every run-time point is
below.

board's console banner and the image's build. A point that fails is recorded with its output; the
check is not turned off to make a run pass.

## Known gaps (recorded, not run)

- **Download mode has no time bound in U-Boot v2026.10.** `fastboot usb` has no timeout; it returns on
  the host's `continue`, on Ctrl-C, or immediately when the board's cable check says no cable. The
  watchdog is fed during the wait (so a flash is safe), which means it cannot be the bound either.
  So "try slots, offer download mode for a bounded time, try again" is met in this form: the slots
  are tried in three passes in a row (a transient failure is retried by the first two), download mode
  is offered by itself, and after a host ends the session the slots are tried once before it is
  offered again. The offer is not bounded in time: a board with no host on a U-Boot without a VBUS
  check waits there, LED on. A timed abort needs a U-Boot change (a board `g_dnl_board_usb_cable_connected`, or a
  patch to `cmd/fastboot.c`), which this repository does not carry. Not invented here.
- A damaged U-Boot proper behind a valid first stage (SPL): `boot.cmd` never runs. Stated, accepted.
- The Linux writer's format is U-Boot's at `v2026.10`. A board on another tag must be re-checked
  against its `env/` sources before its environment is written from Linux.
- Only the primary GPT is read; U-Boot also falls back to the backup. A disk whose primary table is
  damaged is refused by name rather than guessed.
- The fixed-offset form (`uboot_env_device`) supports block devices only; flash and UBI environments
  are refused by name (their writes need an erase).
- `ENV_MMC_EMMC_HW_PARTITION` (the environment in an eMMC boot partition, including the case of the two
  boot partitions, `env/mmc.c:216-231`) is not supported by the raw layout, and the GPT lookup is
  U-Boot's only for the user area (`hwpart == 0`, `env/mmc.c:187`).
- 512-byte blocks only (the MMC case); a 4096-byte-sector device is refused by the GPT reader because
  its header is not at byte 512.
- The `file` form (one `boot-record` file) is refused by name at run time: no raw path in the design,
  not a production slot form.
- The locator `uboot-env.txt` is not in any slot's signed manifest, so the every-boot hash check does
  not see it; the check is its own fit against the device. A change to the boot partition that edits
  the locator is caught only by that fit and the CRC checks of both copies.
- The root copy (`extlinux/extlinux.conf`) is the install-time fallback and is not rewritten at run
  time on the boot-partition form: after a default change the root copy names the install-time
  default. The loader reads the environment's default first, so the root copy starts only when the
  environment is unreadable or the slot it names will not start. The install itself still stages the
  slot's boot files on the mounted boot partition (`docs/slots.md`, "Boot partition writes audit");
  the payload bays (I5i8) move that.
