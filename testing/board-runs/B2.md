# B2: Linux I2C and SPI

Status: untested on board. The fallback and message-building logic is covered by unit tests, but no
transfer has reached real hardware.

## I2C

On the CM5, once `bmi088` (B8) has merged, with a board file naming the bus as `i2c-N`:

1. Run `lemnosd` with no `--sim`, then read the accelerometer through `lemnos-ctl`.
   Pass: readings arrive and change when the board moves.
2. Point a device at an address a kernel driver owns.
   Pass: it reports `BUSY` and keeps retrying. Nothing is forced.
3. Remove the bus's i2c-dev node while it's running, then restore it.
   Pass: the device reports the failure, retries, and recovers without a restart.

## SMBus-only adapter

On any SMBus-only adapter (`i2cdetect -F` shows no `I2C` line):

1. Read and write a multi-byte register run.
   Pass: both match what `i2cget` and `i2cset` report.

## SPI

With a device on `spidevB.C`:

1. Name it in the board file and read its identity register.
   Pass: the value matches the datasheet.
2. Give two devices the same `spidevB.C`.
   Pass: the second reports `BUSY`.
3. Run a transaction with a read and write of different lengths.
   Pass: the shorter half is padded, and the longer half's bytes are correct.
