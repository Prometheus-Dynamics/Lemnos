# G2: the Rockchip NPU as a daemon driver (`drivers/rknpu`, driver `rknpu`)

Status: untested on board. `lemnos-driver-rknpu` gained `Rknpu`, the `#[driver]` type `lemnosd`
now builds in: bound from a board file, `npu/1` served on a claim on the node and the device's
`jobs` stream, health, ticks and the failure rule. What has run on the PC
(`cargo test -p lemnos-driver-rknpu`, 36 tests): the driver bound by a real host from a board
file over the played kernel of `E32.md`, a caller loading a program, attaching buffers and
running it through the host's own frame stream, a run naming no program refused without reaching
the block, another caller refused the program and the program unloaded when its caller goes,
opens failing and backing off 250 ms doubling to 8 s without giving up, a block without an IOMMU
reported as failed and taken once it is confined, a node answering `ENODEV` dropped and opened
again, the real entry bound with a node path that does not exist, and ticks with a claim held
allocating nothing. No test opened a device node, so nothing below has been seen to happen. The
checks in `E32.md` come first; these build on them.

Run it in a local session on an RK3588 board with the vendor kernel and the `rknpu` DRM driver,
as in `E32.md`. Take `/run/lock/board-gpu.lock`. Build on NVMe or SSD, never on the Github HDD.
Unbinds, rebinds and reboots are allowed; report each.

```toml
[[devices]]
id = "npu"
driver = "rknpu"
config = { node = "/dev/dri/renderD129" }   # the node E32 check 1 found, or leave `node` out

[devices.streams.jobs]
buffers = 8
buffer_bytes = 4194304
```

## Checks

1. **It binds and opens the node at the first tick.** Start lemnosd. Expect the device
   `Running`, healthy, and the render node among lemnosd's open files
   (`ls -l /proc/$(pidof lemnosd)/fd`). Record `fuser -v` on the node: lemnosd must be its only
   opener. Then leave `node` out of the board file and expect the same node found by its driver.
2. **A run through the daemon.** From a client, attach the `jobs` stream, write the framed
   program of `E32.md` check 3 into a buffer, call `load`, `attach` slots 0 and 1, and post a run.
   Expect `Done` and the outputs the program writes; `counters` gives one job.
3. **A caller that goes.** Load a program from one client, then end that client's process.
   Expect the program's objects freed (the rknpu debugfs `mm` file, or `gem_names`) and its
   domain loadable again. A second client calling `unload` on the first one's program gets
   `NOT_FOUND`.
4. **The node goes and comes back.** Unbind the NPU's platform device
   (`echo <dev> > /sys/bus/platform/drivers/RKNPU/unbind`), post a run: expect it to complete
   `Failed` and the device's health to read "the node went away: opening it again". Bind it
   again; expect health `Ok` within 8 s, the old program `NOT_FOUND`, and a new load and run
   `Done`. If the kernel answers something other than `ENODEV` on the unbound node, record what,
   because the driver reopens only on `ENODEV`.
5. **No IOMMU.** With the NPU's IOMMU disabled in the device tree, expect health `Failed` ("the
   block is not behind an IOMMU") and every method `NO_DEVICE`, and the device still `Running`.
