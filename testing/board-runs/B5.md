# B5: RP1 PIO I2C

Status: untested on board. No board is reachable from the cloud session. The protocol is tested on a
fake PIO block: the state machine program words, the ACK and NACK decoding, the transfer sequencing,
recovery after a failed transfer, release on drop, and steady-state transfers with no allocation.
Nothing here has run on the RP1 block.

Before the run, take `/run/lock/board-gpu.lock`, and build on NVMe or SSD, never the HDD.

Board file, with the BMI088 on GPIO8 (SDA) and GPIO7 (SCL):

```
bus = "pio-i2c:sda=8,scl=7"
```

On the CM5:

1. Open the BMI088 through the board file and read register `0x00` (chip ID).
   Pass: the accelerometer at its I2C address (0x18, or 0x19 with SDO high) reads `0x1E`, or the
   gyroscope at 0x68 reads `0x0F`. The read succeeds and the value matches the chip's chip ID.
2. Ask the same bus for an address nothing answers, such as 0x2A.
   Pass: the transfer fails with a NACK on that call, and the bus accepts the next call. Step 1
   read after this still passes.
3. Pull SDA low from outside the chip, then read.
   Pass: the transfer fails on that call, and the next read after the line is released returns the
   chip ID. The bus does not stay stuck.
4. Open the same pins from two devices at once, then drop one.
   Pass: both reads succeed while both are open. The block is released only after the last handle
   drops, and a new open after that succeeds.
5. Run 1000 chip-ID reads at 400 kHz and then at 100 kHz.
   Pass: every read returns the chip ID, and the run completes without a stall.
6. Open the bus with the kernel's `i2c-gpio` device still bound to GPIO8 or GPIO7.
   Pass: the open fails with a busy status, and the kernel device keeps working.
