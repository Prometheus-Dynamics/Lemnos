# M41b board run: the bring-up figure is the host's stamp, not the look

Status: untested on board. The host and daemon tests run on the simulated board (`engine/host/tests/running_ok.rs`).
The 250 ms limit has not been measured on hardware.

What this checks: the once-per-bind line `lemnosd: <id>: running ok N ms after bind` now takes its time from
the host's stamp of the moment the device first ran with health Ok (`Host::running_ok_ns`), not from the
daemon's look, which ran every 250 ms. Before this change three sensors on the CM5 each logged 286 to 287 ms,
which is that observation quantization. After it, the figure must not carry that delay.

Setup: the three sensors the board file already binds (the same three that logged 286 to 287 ms before), with
their ids as written in the board file. Build on the solid-state disk, not the HDD, per the board-run rules.

Run directory: `/run/lemnos-m41b` (tmpfs). The script's last step removes it.

Steps, in order, under `flock /run/lock/board-gpu.lock`:

1. Build `lemnosd` and `lemnos-ctl` for the board target (`aarch64-unknown-linux-musl`, profile `service`).
   Pass: the build succeeds on the solid-state disk.
2. Note the daemon and any driver service that holds the three sensors, and stop them. Record what you stopped.
   Pass: nothing else holds the three sensors.
3. Start `lemnosd --board board.toml --socket /run/lemnos/lemnosd.sock` with stderr captured to
   `/run/lemnos-m41b/stderr.log`. Keep it running for at least 5 binds per sensor (unbind and bind each sensor
   with `lemnos-ctl` between runs, so each bind gets its own line).
   Capture: every `running ok N ms after bind` line, with its device id and bind number.
4. For each bind, time the bring-up independently: the driver's own bring-up log line (or, where the driver has
   none, the time from the bind command to the first `Ok` read from `lemnos-ctl get`, sampled every 10 ms).
   Capture: the independent time next to the daemon's N.
   Pass: for each bind, |N - independent| is within 250 ms. The old look-time figure was up to 250 ms late,
   so a figure that is no longer quantized to a 250 ms look is the sign the stamp is in use. Record whether the
   three sensors still all show the same N (286 or 287): if they do, the check fails and the stamp is not
   being used.
5. Stop the daemon, put back whatever step 2 stopped, and check the three sensors are bound as they were.
   Pass: the same devices are bound with the same ids.
6. Last step: `rm -rf /run/lemnos-m41b`. Record the result in this file under each step, with the command output
   and the timings. Change `Status:` from `untested on board` to what was run and when, and list what was stopped
   and started (AGENTS.md, Board runs).
