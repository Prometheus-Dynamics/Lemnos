# F2f1 board check: the receiver and the front end claim their parts

Status: NOT RUN on the board. Written as the check for the per-part claim (kernel/lemnos_rp1_csi2.c,
LEMNOS_RP1_CSI2_IOC_CLAIM), to be run in Phase 2 with the rest of the camera chain.

What the host and QEMU checks cover (see the PR): two files claim different parts; a second claim of
a part is EBUSY; observing calls work unclaimed while another file drives; a driving call without a
claim is EPERM; closing a file releases only its part.

## Board steps still to run

2. Chain run (sensor -> receiver -> front end -> back end): receiver counters and the sensor latch read
   while the front end streams. Before this change both failed with EBUSY (F2d record, open item 2).
3. Receiver unbind and rebind while the front end's file is open: the front end's claim ends with its
   file, not with the receiver's; the receiver's counters stay readable from a second file.
4. Record each measured number here with the commit. Nothing is measured yet.
