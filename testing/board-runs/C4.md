# C4: GPIO and PWM through the module, on a board

Run on the board 2026-11-11, in part: reads of a free input and PWM with its output off. Nothing was
driven, so checks 1 to 3 and the waveform in 4 were not run.

On the CM5, A/B against the character device and the sysfs PWM interface, same pin:

1. Drive an output through `/dev/gpiochipN` and through the module. Measure both on a scope or a second pin; same level, record time per toggle.
2. Close the claim with the output high: the pin stays high.
3. Edges: loop a pin to an input, toggle, record edge stamps through `read()` on the claim. Compare count and order against the character device's line events.
4. PWM: same period and duty through sysfs and through the module on the fan or a spare channel. Same waveform on a scope. Close the claim: the output keeps running.

## Result, 2026-11-11

Run 2026-11-11 on the CM5 (Raspberry Pi Compute Module 5 Rev 1.0, Raze #2), kernel `7.2.9-v8-16k`,
with `lemnos.ko`, `lemnosd` and the tools from PR F2a, built on NVMe and copied to
`/tmp/lemnos-run/` on the board. Raw logs are kept off the repository.

Same command and rounds as C3. Only a line and a channel the board's files leave free were used,
and neither was driven.

- GPIO: `gpiochip15:27` (free, unconnected) taken as an input with its bias as it was, read 2000
  times: stock 1278 ns, module 1241 ns median, 0 allocations. A second owner is refused on both
  routes. Checks 1 to 3 need a driven output and a loop or a scope: not run.
- PWM: `pwmchip0:0` configured with its output off, duty alternating: stock about 25.1 µs median
  (p99 33 to 40 µs), module 3945 ns (p99 about 4.5 µs), 0 allocations, left off. The waveform and
  the close behaviour need an enabled output and a scope: not run.
- Left on the board: pin 27's function reads `gpio` input where it read `none`, and `pwm-0`'s
  requested configuration reads disabled 250000/1000000 ns where it read 0/0. Neither drives
  anything; there is no tool on the board to set them back, and a reboot clears both.
