# I2: frame streams on the shm rings, on the reference board

Status: untested on board. The frame streams of `lemnosd`, the client and the C API are the shm
family's rings (`docs/ring.md`, `docs/streams.md`). The module's own stream ring is not moved yet
(TODO, I2b), so the receiver and ISP paths through `lemnos.ko` keep the protocol they had, and a
run here checks that the consumer side still receives their frames.

What has run on the PC: the shm crates' tests, the wire ring's tests (`cargo test -p lemnos-wire
--features testing`), the host's stream tests, the client's, the daemon's and the contracts' and
drivers' stream tests, all with the test memory of the PC and no dma-heap. No frame from real
hardware has been checked on this build.

Before running: take `/run/lock/board-gpu.lock`, use the CM5 (Raze #2), and build on NVMe or SSD,
never on the Github HDD. Record the date, image and commit at the end.

## 1. The camera path

Run the camera proof (`testing/crates/camera-proof`) on the reference board's camera, for 120
frames at 120 frames a second, through `lemnosd`. Each frame must arrive once, in sequence, with
the sequence and identity the producer published, and with no drop when the consumer keeps up.
This is the path the `lemnos.ko` receiver feeds (`D9.md`, `D5.md`, `D16.md`): rerun the checks
those records made, unchanged.

## 2. Consumer-filled streams

The ISP's config and input streams are consumer-filled (`camera.isp/1`). Run `pisp-be` on the
board with its job stream once: a configuration written through the writable consumer, the job
posted, the completion read back on the frame stream (`D15.md`, `H5a.md`). A stream whose buffers
are dma-bufs keeps its planes (`H5a.md`: a frame in planes straight into a stream).

## 3. Standby and dma-bufs

Capture straight into a stream's dma-bufs and check the vendor capture drivers take them
(`E39.md`). Run the standby case of `H5a.md`: capture with nobody attached, then a consumer
attaching gets the newest frame at once.

## 4. Faults

A consumer that stops collecting jobs past the job ring's capacity, and one that holds every
buffer, lose only their own stream (`H3c.md`, `E2.md` for the job streams of the contracts).

## 5. Timing

Record `clock_gettime(CLOCK_MONOTONIC)` for 100 frames and check each frame's timestamp lies
below it and above the previous frame's (as in `I3.md`, section 1), now through the shm frame
ring.
