# E15 board run: stateless video decode

Status: untested on board. The parser's tests (including every truncation and single-bit
corruption of a real stream's headers) and the session and decoder tests on a node that plays a
stateless device back have passed. No frame has gone through this code on a real decoder. Dev's
code, which this ports, decoded the same frame byte for byte on the BCM2712 (`rpi-hevc-dec`) on
2026-11-03.

Run in a local session after this PR merges, on the CM5 (Raze #2). Take `/run/lock/board-gpu.lock`.
Build on NVMe or SSD, never on the Github HDD. Report CM5 timings only. Only check 4 unbinds a driver
(and binds it back): the decoder is the kernel's `rpi-hevc-dec`, used through its video node and
its media device.

## Getting the node and the reference

```sh
for v in /sys/class/video4linux/video*; do echo "$v $(cat $v/name)"; done   # the rpi-hevc-dec node
v4l2-ctl -d /dev/videoN --all | head -30   # Stateless HEVC output (S265), M2M multi-planar
media-ctl -d /dev/mediaM -p               # lists that video node
```

The reference is the fixture (`drivers/hevc/tests/fixtures/idr320.h265`, one 320x240 IDR) decoded
on another machine to linear NV12, 115,200 bytes, for example
`ffmpeg -i idr320.h265 -pix_fmt nv12 -f rawvideo idr320.nv12` or a GStreamer decode. Record which
decoder made it.

## Checks

1. **HEVC decode matches.** As root (or with access to the video and media nodes):

   ```sh
   LEMNOS_M2M_DECODE_NODE=/dev/videoN LEMNOS_M2M_DECODE_REFERENCE=/path/idr320.nv12 \
     cargo test --release -p lemnos-driver-m2m-decode --test board -- --ignored
   ```

   Pass: 0 bytes differ from the reference, and 300 decodes of the same frame on one session
   all match the first. Record the capture format the driver answered with (`Nc12` was dev's).
   Run it three times.
2. **Timings.** With the same frame, time the first `decode` (open, stream on, first frame) and
   the median of the next 299 (one request each). Dev's figures for comparison: open 0.9 to 1.3
   ms, stream on 1.1 to 1.2 ms, request run 181 to 192 us, queue to decoded frame 188 to 200 us.
3. **No allocation on the frame path.** Run the frame loop of check 1 under the counting
   allocator (as the unit test `a_decoded_frame_allocates_nothing_once_open` does on the mock);
   0 allocations from the second frame on.
4. **Recovery.** While frames run in a loop (a small program over `HevcDecoder` and
   `LinuxNode::open`), unbind the decoder (`echo <device> >
   /sys/bus/platform/drivers/rpi-hevc-dec/unbind`, the device name from the node's
   `device` link), wait 20 s, and bind it again. Report the unbind and bind. Pass: the loop's
   `decode` returns `Device` and then `BackingOff`, with delays of 250 ms doubling to 8 s and
   holding there; after the bind the next due call reopens (the node may have a new number: the
   program finds it again with `LinuxNode::find("rpi-hevc-dec")`) and frames match again.
   Nothing panics and the decoder never stops trying.
5. **dmesg** clean of `rpi-hevc-dec` errors through all of it; `vcgencmd get_throttled` 0x0.

Record the kernel version, the node and media paths, and each result here.
