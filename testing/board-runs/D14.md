# D14 board run: V4L2 backend

Status: untested on board. Every test in this PR runs against crafted structures and ordinary files;
no test opens a device node.

On a board with a CSI or USB capture device and, for the media-controller and request checks, a media
device. Hold the board run lock, and record the kernel version and driver names here.

1. `VideoDevice::open`, `capabilities`, `formats`, `frame_sizes`: values match `v4l2-ctl --all`.
2. `MmapQueue::new` on a capture queue with 4 buffers: `map_buffer` lengths equal `sizeimage` of the
   format, and queue, `dequeue_within`, `payload` give a frame of the expected size for 300 frames.
   Repeat on a multi-planar queue.
3. `export_buffer` a capture plane, and import it through `MmapQueue::importing` on an output queue:
   the frame arrives intact.
4. `MediaDevice::topology` against `media-ctl -p`: same entities, pads and links. `setup_link`
   enables and disables one mutable link.
5. `Subdev`: `mbus_codes`, `frame_sizes`, `format`, and `routing` on a subdevice with streams.
6. Controls: `query_controls` matches `v4l2-ctl -L`; `set_controls` and `control` round-trip one integer
   and one compound control; `set_controls_in_place` in a request is applied with that request.
7. `Events`: frame-sync events arrive once per frame with increasing sequence.
8. Stateless decode: one HEVC frame through an output and a capture queue with `Sps`, `Pps`,
   `SliceParams`, `DecodeParams` set in a media request, using `v4l2::hevc` from `lemnos-linux-sys`.
9. Unplug a USB capture device mid-stream: `dequeue` errors with `is_no_device`, nothing panics.
