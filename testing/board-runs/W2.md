# W2 board run: indicator states on the CM5

Status: untested on board. The pattern grammar, the frames each pattern draws over time, the state
set, the backoff of a failed write and the steady state's allocations are covered by tests over a fake
`pixels/1` device on the cloud host (`drivers/indicator/tests`). The system-slots driver's install
phases on an indicator are covered by its tests (`the_indicator_shows_each_phase_of_an_install...`).
No frame has reached a real LED.

Run in a local session after this PR merges. Take the board lock named in `AGENTS.md`
(`/run/lock/board-gpu.lock`) before starting, use the CM5 only, and build on NVMe or SSD, never on the
Github HDD. Report CM5 timings only.

The board file binds a `ws2812` strip as in B16 (`count = 16`), and an `indicator` on it, with one
pattern changed so the failure is easy to see:

```toml
[[devices]]
id = "indicator"
driver = "indicator"
uses = { pixels = "ring-pixels" }
config = { "state.failed" = "blink #ff0000 period=400", brightness = 128 }
```

The states are sent through `indicator/1`'s `set(state, progress)`; `states` lists them.

1. Bind and health. Start the service with the board above.
   Pass: the `indicator` is running, its health is ok, and `states` answers
   `idle,receiving,writing,verifying,done,failed`.
2. Idle. Set `idle`, wait 300 ms.
   Pass: every LED is off, and the strip is not left in the colour it had before.
3. Blink. Set `failed` with no progress, and time the LEDs over 2 s.
   Pass: red at half brightness (128 of 255), on for 200 ms and off for 200 ms, repeating.
4. Bar. Set `writing` with progress 0, then 500, then 1000, then none.
   Pass: 0 LEDs lit, then 8 of 16 green, then all 16, then every LED at the dim colour (the built-in
   `writing` pattern: `bar #00c040 off=#001000`, at the board's brightness of 255).
5. Refusal. Set `reboot` (not a state) and set progress 1001.
   Pass: both refused with `INVALID_ARGUMENT`; the strip keeps its last frame.
6. Cost. Leave `done` (solid) on for 60 s with the CPU counter running.
   Pass: no further frames are written after the first one (the pattern never changes, so the driver
   asks for no ticks).
7. A job on the board. Run a first flash or a slot install (`W1.md` or `I5.md`) with the indicator on
   `uses`: the strip shows `receiving`, then `writing` or `verifying`, then `done`.
   Pass: the states follow the job, and the job ends `done` on a success and `failed` on a refused
   bundle.

Record the board, the kernel, the build's commit, each check's result, and the CM5 timings of the
frame writes (the time from `show` to the last LED's bytes in the SPI transfer).
