# D12: uvc

Status: untested on board. Descriptor parsing, taking the interfaces from the host's own video
driver, probe and commit, the alternate setting, frame assembly, writing frames into the stream,
and the failure rule are covered by tests replaying descriptors and isochronous packets through
mock USB devices, one of them on a real host with frames read off the real ring. No test has
opened, detached, claimed or read a real USB device, and no frame from a real camera has passed
through this driver.

## Bench webcam frames

Run with the board lock named in `AGENTS.md`. The driver is not in lemnosd's built-ins yet: a
maintainer runs `scripts/generate-builtins.py` after merging, or the run uses a build that
registers it. Give the camera a board entry, named by its port (`usb:<bus>-<port>[.<port>...]`)
or by its vendor and product (`usb:<vvvv>:<pppp>`):

```toml
[[devices]]
id = "webcam"
driver = "uvc"
bus = "usb:1-1.4"
config = { frame_bytes = 4147200 }

[devices.streams.frames]
buffers = 4
buffer_bytes = 4147200
```

`frame_bytes` and `buffer_bytes` must be equal, and at least one frame of the largest format used.

Checks, in order:

1. Before starting lemnosd, `ls /sys/bus/usb/drivers/uvcvideo/` shows the camera's interfaces
   bound. Start lemnosd: the driver binds, both video interfaces leave `uvcvideo` (the links are
   gone from that directory, `/dev/video*` for the camera disappears), health is `Ok` and the
   description says `state: idle`.
2. `format_count` and `format` match `lsusb -v` for the camera: every uncompressed and MJPEG format,
   every frame size, every interval. Frame-based formats are left out.
3. `select_format` an uncompressed mode and an MJPEG mode in turn, then `start`, and watch the
   camera with `usbmon`: `SET_CUR(VS_PROBE)`, `GET_CUR(VS_PROBE)`, `SET_CUR(VS_COMMIT)`, then
   `SET_INTERFACE` to the smallest alternate whose bandwidth covers `dwMaxPayloadTransferSize`.
4. Streaming with no consumer attached: `counters` shows `dropped` rising at the camera's rate,
   `frames` at 0, health `Ok`, and the host stays responsive.
5. Attach a consumer to `frames`: each frame's bytes are the picture (save one MJPEG frame and open
   it as a JPEG; for YUYV, `bytes` equals width x height x 2), the sequence counts up, `frames` in
   `counters` matches the camera's rate over 60 s. Record the rate of `errors` at each frame size:
   `iso_in` has one transfer in flight at a time, so at high bandwidth some packets between
   transfers are lost; compare against a reference that queues several transfers.
6. A frame larger than `buffer_bytes`: set `frame_bytes` and `buffer_bytes` below the largest MJPEG
   frame. `dropped` rises, health says frames are larger than the stream buffer, and no truncated
   frame appears.
7. Unplug during streaming. Health becomes `Failed` with `the device is gone: retrying, and waiting
   to be opened again by name`, retries never more than 8 s apart, no panic, the rest of the host
   is unaffected. Calls to the device answer `NO_DEVICE`.
8. Plug it back in (the kernel binds `uvcvideo` again). Call `counters` until the host drops the
   driver (5 `NO_DEVICE` in a row by default); at the next retry the host binds it again, the
   device is opened by name, `uvcvideo` is detached again, and `select_format`/`start` streams as in
   step 5. Without calls, the driver stays `Failed` and keeps retrying the dead handle: say so in
   the report, it is a known gap.
9. `stop`: the camera returns to alternate setting 0 (`usbmon`, or the camera's LED goes out).

Known gaps, not checks: hotplug binding (the engine has no binding from a `usb` hotplug event, so
the board file must name the camera), and a ticking driver can't ask the host to bind it again
(step 8 needs a caller).
