# J4 board run: gain law and frame identity on the reference board

Status: untested on board. Nothing here was run on hardware. The sensor contract's gain law and
timing rule are checked against the tree's facts only.

Run in a local session after this PR merges, on the CM5 (Raze #2), with an OV9782 on the board
and the sensor's board entry from D8. Take the board lock named in `AGENTS.md`,
`/run/lock/board-gpu.lock`. Build on NVMe or SSD, never on the Github HDD. Report CM5 timings only.

## Checks

1. **Gain is linear in sixteenths** (`GainLaw::Linear`, `ANALOGUE_GAIN_RANGE`). With the scene lit
   and exposure fixed, set analogue gain codes 0x10, 0x20 and 0x40 (gains 1, 2 and 4). Pass: mean
   brightness above the black level doubles at each step, within the noise of the scene.
2. **Frame identity is 0 on every frame.** Through the receiver's frame stream (`rp1-csi2`, or
   `k230-capture`, or `sunxi-vin` on their boards), read each frame's identity. Pass: every frame
   reports identity 0, and sequence numbers count up from the receiver's start with no gaps while
   the stream is kept drained.
3. **Which frame a post shows on.** Already run as D10 (`testing/board-runs/D10.md`). Its result
   decides whether the timing rule in `contracts/camera-sensor` holds: a post whose group launch
   completes during frame `F` shows on `F + 2`, all three controls together.
4. **Embedded data.** Not applicable to the OV9782 (`SensorInfo::embedded_data` is `None`).
   Receivers in the tree answer `embedded_stream` with an empty name, so there is no stream to read.
   No check is needed until a sensor with embedded data is on a board.
