# B18: raw-bus

Status: untested on board. The calls, the closed write policy, the failure rule and the sizes that
cross the socket are covered by unit and integration tests over the simulated I2C, SPI, GPIO and PWM
resources. No call has reached a real bus through this driver.

Run on the CM5, with a board file that binds one raw-bus device the resources to check. Take the
board lock named in `AGENTS.md` before starting. Bus names are the ones the Linux backend resolves
for the I2C, GPIO and PWM work (B2 and B3).

The policy is closed by default. With no `writes = true` and no `allow_i2c`, every I2C transfer is
refused, and so is every SPI transfer, `line_set`, an output line at bind and `pwm_set`. Each step
below sets only what it needs.

1. I2C read: a device `raw` with `uses = { i2c = "<an I2C bus>" }` and `config = { allow_i2c =
   "<the chip's address>" }`. Call `i2c_transfer(address, write, read_len, into)` with the chip's
   register pointer as `write`, and expect the register's datasheet value back. Writes stay refused.
2. Refusal on the bus: the same device with an address that is not on `allow_i2c` (for example the
   address of another board device on that bus). Its transfer must return `NOT_PERMITTED`, and the
   kernel must see no transaction (check with the bus's own counters or a logic analyser).
3. Writes: add `writes = true`. The chip's register write must now land. Without it, the same write
   must return `NOT_PERMITTED` while the read-only transfer of step 1 still passes.
4. GPIO: a device with `uses = { line = "<an unused line>" }`. With `writes = true` and
   `line_direction = "output"`, `line_set` and `line_get` must drive and read the line. With
   `writes` unset, bind with `line_direction = "output"` must be refused and the line must not change.
5. PWM: a device with `uses = { pwm = "<an unused channel>" }` and `writes = true`. `pwm_set` with a
   20 ms period must show on the sysfs channel, and `enabled = false` must disable it.
6. SPI: a device with `uses = { spi = "<an SPI device>" }` and `writes = true`. A JEDEC ID read
   (`spi_transfer` with `0x9f` and three bytes back) must return the flash's ID.
7. Failure: unplug or stop the chip, call `i2c_transfer`, and expect the call to report an error and
   health to read `Failed`. Plug it back in, call again, and expect success and health `Ok`. No retry
   timer should run in between.

Record the outcome of each step here with the output of each call.
