# B20 board run: lemnos-orion publishes every device on the CM5

Status: untested on board. Run against a real Orion node (comm core and node logic, Orion `next`
at the revision `service/orion/Cargo.toml` pins) on a PC, with lemnosd on the simulated board:
see "The PC run" below.

The service has no code for any device, so the check is that each device lemnosd lists on the CM5
is a resource in Orion with its topics and actions, and that both sides coming and going are
followed. The host tests cover the mapping and the retries with a simulated lemnosd and an
in-process comm core and node logic.

Setup: lemnosd running on the CM5 with the board's file, and Orion's comm core and node logic
running (`orion comm`, `orion node`). Build `lemnos-orion` for aarch64 on the NVMe or SSD, not the
HDD, and run it under the board lock (`/run/lock/board-gpu.lock`) for the whole run. `orion` below
is Orion's command line, `--address` the comm core's socket.

1. Start `lemnos-orion` with `LEMNOSD_SOCKET` set, and `ORION_NODE_ID` set to the node's name.
   Pass: the log says `connected to Orion node <name>; N devices published`, with N the number of
   devices `lemnos-ctl list` shows, and no `not publishing` line.
2. `orion resource list lemnos.`.
   Pass: one `lemnos.<device>` resource for each device `lemnos-ctl list` names, of the kind
   `lemnos.device`. A device with no plain value item still has its resource and status topic.
3. For every device, compare `orion resource show lemnos.<device>` with `lemnos-ctl list`.
   Pass: a running device is `Ready`, one retrying or with failed health `Failed`, one off
   `Pending`; `orion topic read lemnos.<device>.status` shows the same state, health and reason.
4. For each value item, compare `lemnos-ctl read <device> <item>` with
   `orion topic read lemnos.<device>.values`.
   Pass: the values agree in the item's unit. Items that are not numbers or flags are absent from
   the topic and the log says so.
5. Change a value on the board (tilt the IMU) while `orion topic watch lemnos.<device>.values` runs.
   Pass: the new value appears within one second, with no restart of `lemnos-orion`.
6. For a device with a control item, `orion action run lemnos.<device>.set --resource
   lemnos.<device> --args "<item> <value>"`, then read it back with `lemnos-ctl`.
   Pass: the action ends `Succeeded` and the device holds the value. A value the item does not take
   ends `Rejected` with why.
7. `orion action run lemnos.<device>.power --resource lemnos.<device> --args off`, then `on`.
   Pass: `lemnos-ctl list` shows the device off, then running; the resource is `Pending`, then
   `Ready`.
8. Restart the comm core while `lemnos-orion` keeps running.
   Pass: within 10 s every resource is back `Ready` with its topics live, and the log says
   `connected to Orion node <name> again`.
9. Stop lemnosd (it needs the board lock as well), then start it again.
   Pass: while it is down `orion resource list lemnos.` is empty and `orion topic read` of a
   device's topic says its publisher is gone; nothing shows `running` from before. Within 30 s of
   lemnosd answering again every device is back with its values.
10. Start `lemnos-orion` with `ORION_NODE_ID` set to another name than the node's.
    Pass: the log says `not publishing`, and Orion holds no `lemnos.` resource.

## The PC run

2026-11-13, on the PC that builds Lemnos (no hardware touched): Orion `next` at `61e95a4`, built
from that revision, run as `orion comm` and `orion node` (node name `bench`) from one settings
file; `lemnosd --sim --board docs/examples/sim-board.toml`; `lemnos-orion` with `ORION_NODE_ID=bench`.
Every step above that needs no board passed:

- 1, 2, 3: `connected to Orion node bench; 6 devices published`. Six `lemnos.*` resources, the
  five running ones `Ready`, `lemnos.absent` (no bus on the simulated board) `Failed`, its status
  topic `retrying`, `failed`, `bind failed: Status(-2)`.
- 4: `lemnos.accel.values` read `x = 0 m/s²`, `y = 0 m/s²`, `z = 9.81 m/s²`, as the board file says.
- 6: `set` `target 1000` succeeded and `call` `peek` answered 1015 (the counter counts on each
  read); `set` `count 3` ended `Rejected: count is read-only`; `call` `fail` ended
  `Failed: refused (-5)`.
- 7: `power off` made the counter `off`/`manual` in `lemnos-ctl list`, the resource `Pending`, the
  status `off`; `power on` brought it back `Ready` with its count moving.
- 8: comm core stopped and started: `connected to Orion node bench again`, every resource back,
  values readable, `call` working. Node logic stopped and started: every resource back.
- 9: lemnosd stopped: `orion resource list lemnos.` empty at once; a reader holding the status
  topic read `state = gone`, `reason = lemnosd is not there`, never `running`; a new reader found
  the topic undeclared. lemnosd started again: all six back within 4 s, the held reader went on to
  `running`, and the first `call` after the return succeeded.
- 10: a second bridge with `ORION_NODE_ID=other` logged `not publishing`.

Two faults the run found were fixed before landing: the first action after lemnosd came back
failed with "not connected" (the call connection now reconnects), and a device not running when
the bridge connected never got its values or actions once it ran (the bridge now reads the
devices again).
