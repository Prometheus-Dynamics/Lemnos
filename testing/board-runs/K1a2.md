# K1a2 board run: the L2 window of the VEPU541 H.264 encoder (`lemnos-driver-rkvenc`, rk-mpp windows)

Status: untested on board. Nothing here was read or written on a device. The second window and the
multi-run job are checked on rk-mpp's played kernel, and the L2 layout is pinned to the header.

This PR does not add the VEPU580 (second-generation) block: its kernel translates through the
session's table into per-class buffers without a bound, so it is not yet a checked block. See the
PR body.

The run needs the same board as K1a: a VEPU541 H.264 encoder node behind the vendor kernel's
`/dev/mpp_service`, bound to rk-mpp. Build on NVMe or SSD, never on the Github HDD. Module loads and
unbinds are allowed; report each.

## Checks

1. **Second window is reached.** Submit one job whose write side is the K1a set and
   whose second run is `set_l2` of `iprd_tthdy4` (word 1, upper half) to `0x1234`. Read the L2 words
   back with a second job whose read is `L2_FIRST`, count 2. Pass: word 1 reads `0x12340000`, the
   completion is Done, and the write side's read-back is unchanged from K1a's check 2.
2. **The job's writes do not overlap the first window.** Its messages on the device are table,
   the L1 write, the L2 write, the read. Pass: no fault and the L1 read-back is equal to the value
   written.
3. **Refusals never reach the device.** A second-window address, or a write across word 780, is
   refused by rk-mpp with the device untouched (`calls` unchanged in the played test).

Record each result with the kernel version and the board's device tree compatible string.
