# M32: a stated camera link reads ok when the receiver cannot say what is wired

Untested on board. The change is in the sensor's link check (`contracts/camera-sensor`, `check_link`), and
the sensor driver (`drivers/ov9782`) takes it. The c1 run on the reference camera board is the case it fixes:
`lemnos-ctl chain cam0-sensor` printed `cam0-sensor ov9782 running degraded camera.sensor/1 (the linked
receiver cannot say what is wired to its input)` with 600 frames and 0 drops.

Checked on this PC: `testing/crates` sim chain (the real ov9782 driver, the simulated receiver answering
NOT_SUPPORTED as rp1-csi2 does on c1), through the real service and `lemnos-ctl` (`list`, `chain`,
`describe`), in `service/ctl/tests/link_health.rs`.

## Board check (after landing; read-only, needs the coordinator's go-ahead to touch the board)

1. `lemnos-ctl list` on the camera chain: the `cam0-sensor` row reads `running  ok  camera.sensor/1  -> cam0-receiver`
   with no reason after it.
2. `lemnos-ctl chain cam0-sensor`: the first row reads the same, with no reason.
3. Frames still flow: the chain proof's frame count and drops are as in c1 (600 frames, 0 drops).

Changes nothing on the board: no slot, module, boot file or reboot.
