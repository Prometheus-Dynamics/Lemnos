# Q2: the reference board's device tree, generated

Status: untested on board. The overlay below was made by `lemnos-ctl tree` from
`testing/boards/reference.toml` and the map `socs/bcm2712-rp1.toml`. It compiles with `dtc -@` and
applies to the base tree (`bcm2712-rpi-cm5-cm5io.dtb`, from the kernel build) with `fdtoverlay`.
Nothing has been loaded on the board. The check at start has not been run on the board.

This record was made again under Q2d, when the board file became the shape of a managed board. Three
things changed in the outputs, and each is a correction or an addition:

- The camera I2C bus is the RP1's `i2c@88000` (`rp1_i2c6`), not the SoC's own `i2c@7d005600`. The base
  tree's alias `i2c10` is `/axi/pcie@1000120000/rp1/i2c@88000` (`i2c10 = &i2c_csi_dsi0` in
  `bcm2712-rpi.dtsi`, and `i2c_csi_dsi0: &i2c6` in `bcm2712-rpi-cm5io.dtsi`). The SoC's own node is
  the label `i2c10`, which is why the old map read the wrong path. Its pins are `rp1_i2c6_38_39`
  (GPIO38, GPIO39): the pin group the CAM/DISP 0 connector's bus uses in that file.
- The watchdog, the USB gadget (UDC `udc:1000480000.usb`, node `/axi/usb@480000`), the camera
  receiver, the PiSP back end and the PIO block are now enabled by devices that name them.
- The reference board's devices are the managed set: the system identity, slots and reboot, the
  watchdog as the keep-alive, the USB gadget, the LED strip, the IMU and magnetometer on the PIO I2C
  bus, the power monitor on `i2c-1`, the camera chain with its links, and the fan.

Compile and apply on the build host (`dtc` and `fdtoverlay` are installed here):

```sh
lemnos-ctl tree testing/boards/reference.toml --socs socs -o board-overlay.dts --boot boot.txt --modprobe lemnos.conf
dtc -@ -I dts -O dtb -o board-overlay.dtbo board-overlay.dts
fdtoverlay -i bcm2712-rpi-cm5-cm5io.dtb -o applied.dtb board-overlay.dtbo
```

The overlay has no includes: the generator writes node paths and labels only, so no kernel include
directory is needed. Read back from `applied.dtb` (`dtc -I dtb -O dts`): `i2c@74000`, `i2c@88000`,
`pwm@9c000`, `csi@110000`, `pio@178000`, `usb@480000`, `watchdog@7d200000` and `pisp_be@880000` are
`okay` with their pin groups; `cam0_reg` is `disabled`; the alias `i2c10` is `/axi/pcie@1000120000/rp1/i2c@88000`.

## The overlay

```dts
// Generated by `lemnos-ctl tree` from board "reference". Do not edit: change the
// board file or the SoC map, and generate again.
// Every fragment says why it is here. Node paths are the base tree's.
/dts-v1/;
/plugin/;
/ {
	// i2c: an I2C bus on RP1 (designware); the board's i2c-1 (alias i2c1, the name "i2c-1") on GPIO2, GPIO3
	fragment@0 {
		target-path = "/axi/pcie@1000120000/rp1/i2c@74000";
		__overlay__ {
			status = "okay";
			pinctrl-names = "default";
			pinctrl-0 = <&rp1_i2c1_2_3>;
		};
	};
	// the runtime name comes out of alias i2c1
	fragment@1 {
		target-path = "/";
		__overlay__ {
			aliases { i2c1 = "/axi/pcie@1000120000/rp1/i2c@74000"; };
		};
	};
	// i2c: an I2C bus on RP1 (designware): the camera and display connector's bus, the board's i2c-10 (alias i2c10, the name "i2c-10") on GPIO38, GPIO39
	fragment@2 {
		target-path = "/axi/pcie@1000120000/rp1/i2c@88000";
		__overlay__ {
			status = "okay";
			pinctrl-names = "default";
			pinctrl-0 = <&rp1_i2c6_38_39>;
		};
	};
	// the runtime name comes out of alias i2c10
	fragment@3 {
		target-path = "/";
		__overlay__ {
			aliases { i2c10 = "/axi/pcie@1000120000/rp1/i2c@88000"; };
		};
	};
	// pwm: a PWM channel on RP1; the fan's pulse output (a `pwm:NODE:CHANNEL` name's NODE is this path) on GPIO45
	fragment@4 {
		target-path = "/axi/pcie@1000120000/rp1/pwm@9c000";
		__overlay__ {
			status = "okay";
			pinctrl-names = "default";
			pinctrl-0 = <&rp1_pwm1_gpio45>;
		};
	};
	// csi: the camera receiver; the module drives it, and the stock receiver driver must not bind
	fragment@5 {
		target-path = "/axi/pcie@1000120000/rp1/csi@110000";
		__overlay__ {
			status = "okay";
		};
	};
	// block: the PiSP back end, the ISP's processing block; the module drives it
	fragment@6 {
		target-path = "/axi/pisp_be@880000";
		__overlay__ {
			status = "okay";
		};
	};
	// pio: the RP1 PIO block, which the module's state machines and the PIO I2C bus run on
	fragment@7 {
		target-path = "/axi/pcie@1000120000/rp1/pio@178000";
		__overlay__ {
			status = "okay";
		};
	};
	// usb-peripheral: the SoC's USB controller in peripheral mode, for a USB gadget
	fragment@8 {
		target-path = "/axi/usb@480000";
		__overlay__ {
			status = "okay";
			dr_mode = "peripheral";
		};
	};
	// watchdog: the hardware watchdog, on for a managed board
	fragment@9 {
		target-path = "/soc@107c000000/watchdog@7d200000";
		__overlay__ {
			status = "okay";
		};
	};
	// disabled: base "module-io" /cam0_reg: the camera power regulator's enable pin (RP1 GPIO34); a Lemnos power switch drives it; the board gives gpio:pinctrl-rp1:34 to Lemnos
	fragment@10 {
		target-path = "/cam0_reg";
		__overlay__ {
			status = "disabled";
		};
	};
};
```

## The boot fragment

The firmware reads this before the kernel runs. Its syntax for these pins is not verified on the
board: the line for the fan header is the one to check first.

```
# Generated by `lemnos-ctl tree` from board "reference". The firmware reads these
# before the kernel runs, so each line holds its level from power-on until the
# kernel drives it. Syntax not checked on board.
# gpio:pinctrl-rp1:45: boot high: the fan header's line: at full speed from power-on, until Lemnos's fan driver takes it
gpio=45=op,dh
```

## The module configuration

```
# Generated by `lemnos-ctl tree` from board "reference". Do not edit: change the board file or
# the SoC map, and generate again.
# The kernel module owns the nodes below, and each stock driver named by a blacklist is
# kept off them when it loads. Install in /etc/modprobe.d/. A driver built into the kernel
# is not stopped by a blacklist: check it at start (lemnosd reports it).
# csi0: the camera receiver; the module drives it, and the stock receiver driver must not bind. Compatible raspberrypi,rp1-cfe, given to the module as owned
# pisp-be: the PiSP back end, the ISP's processing block; the module drives it. Compatible raspberrypi,pispbe, given to the module as pisp_be
options lemnos owned=raspberrypi,pispbe,raspberrypi,rp1-cfe pisp_be=raspberrypi,pispbe
# the stock driver for a node the module owns: its node must not bind it
blacklist pispbe
# the stock driver for a node the module owns: its node must not bind it
blacklist rp1-cfe
```

## What is not checked on board

- Whether the board's loader applies the overlay, and whether the stock drivers bind the enabled
  nodes, is not yet seen on the board.
- The PWM channel's name: a `pwmchip` number is set by the kernel at probe, so the name the fan
  driver uses cannot be read from the tree. The fan names its channel by `pwm:NODE:CHANNEL`.
- The boot fragment's syntax on the RP1 pins.
- The power monitor's chip and shunt (`ina238`, `0x40`, 10 mOhm, 2 A) are the values of an earlier
  board run on `i2c-1`; they are not re-read here.
- The IMU and magnetometer on the PIO bus (`pio-i2c:sda=8,scl=7`): the magnetometer is on that bus as
  the managed set has it. An earlier board run had the magnetometer on `i2c-1` at 0x10 instead.
- The camera chain's stream sizes are this record's own: the front end has a config stream only, and
  the back end's are as the full example's. The receiver's node is the module's, and the front end
  shares it.
