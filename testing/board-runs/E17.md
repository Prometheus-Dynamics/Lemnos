# E17 board run: the Rockchip IEP2 deinterlacer

Status: untested on board. The layouts (matched against `gcc` on a transcription of the vendor
structures), the checks that keep a job inside its dma-bufs and the driver's reopen and backoff
have passed their tests (`drivers/rk-iep/src/layout_tests.rs`, `drivers/rk-iep/src/tests.rs`). No
job has gone through this code on a real block, and none can yet: issuing the `/dev/mpp_service`
call needs a safe wrapper that does not exist on `next` (it belongs in `drivers/rk-mpp`, E16, or
its `-sys` crate). Everything the code depends on was read from rockchip-linux/kernel
`develop-6.1` at `77168c8d5ab82399f65a80e9f807b50ba37cf483`: `include/uapi/linux/rk-mpp.h`,
`drivers/video/rockchip/mpp/{mpp_iep2.c,rockchip_iep2_regs.h,mpp_common.c,mpp_common.h}`.

Run in a local session once a `Device` over the service exists, on an RK3588 or RK3568 board
running the vendor kernel with `mpp_service` and `mpp-iep2` bound (`ls /dev/mpp_service`,
`cat /proc/mpp_service/*/...` or `dmesg | grep iep2`). Take `/run/lock/board-gpu.lock`. Build on
NVMe or SSD, never on the Github HDD. Module loads, unbinds and rebinds are allowed; report each.

## What the code assumes and the board must confirm

1. **Stride unit.** The code gives the block every stride in 4-byte words (byte stride / 4). The
   source does not say the unit. Run a 1920x1088 NV12 `I2O2` job from a luma ramp (row `y` holds
   `y * 255 / 1087`) with stride 1920 and again with stride 2048. Pass: both outputs match the ramp
   row for row. If the output is a squeezed or repeated picture, the unit is bytes: record it, and
   the stride conversion changes (the extents are already checked in bytes either way).
2. **Output chroma stride.** The output has one stride register. Pass: the chroma of check 1's
   output at stride 2048 is grey (128) on every line and the bytes between 1920 and 2048 of each
   line are untouched (fill them with `0x5a` first).
3. **Scratch size.** The motion data and motion vector buffers are required to hold
   `2 * width * height` bytes each, a bound chosen without the source giving one. Fill each with
   `0xa5`, followed by a `0xa5` guard page, and run 30 `I5O2` jobs on moving content (a ramp
   shifted 3 pixels per frame). Record the highest byte offset written in each. Pass: the guard is
   untouched. If the highest offset is well below the bound, record it; the bound can be lowered.
4. **Extents stay inside.** For each of NV12, NV21, NV16, NV61 and planar 4:2:0 input, and NV12 and
   NV16 output, place every plane in its own dma-buf of exactly its checked size followed by a
   guard page of `0xa5`. Run `I5O2`, `I5O1T`, `I5O1B`, `I2O2`, `I1O1B`, `Pd` (each `PdComp`),
   `Bypass` and `Dect`. Pass: every guard is untouched and no IOMMU fault is logged (`dmesg`).
5. **The left-out mode.** `I1O1T` is not reachable from the crate. With a local patch (never
   committed) adding it, run one job with the current frame's buffer followed by a guard page.
   Record whether the block read past the buffer (`dmesg` shows the vendor driver's aux page
   mapping, or an IOMMU fault at the buffer's end). This says whether the mode can come back.
6. **Results.** `dect_osd_cnt` is at most 8 and `mv_hist` sums to the tile count of the frame on a
   still picture. Record the numbers.
7. **A dropped job.** Run a job naming a memfd (not a dma-buf) for the motion data, through a local
   test only. The vendor driver drops the task without an error. Record what the call returns and
   what `Results` holds; the driver's documentation says it comes back as a job that ran.
8. **Recovery.** While jobs run in a loop (on the monotonic clock), unbind the `mpp-iep2` platform
   device, wait 20 s, bind it again. Report both. Pass: `run` returns `Device`, then `BackingOff`
   with delays from 250 ms doubling to 8 s and holding; after the bind the next due call opens the
   service, binds the IEP2 again and jobs run, with the backoff cleared.
9. **No allocation.** 1000 jobs on an open file, built and run, under the counting allocator.
   Pass: 0 allocations.
10. **Buffers are let go.** 50 jobs each with new buffers dropped after the job, then
    `release_buffers`. Pass: `/sys/kernel/debug/dma_buf/bufinfo` is back where it started after
    `release_buffers`, and not before.
