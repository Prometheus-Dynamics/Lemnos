# E9 board run: rkisp (ISP21, ISP30, ISP35)

Status: untested on board. What landed is the layouts (`drivers/rkisp-sys`), the generation table,
the ISP path plan over a media graph and the per-job checks (`drivers/rkisp`). They pass their
tests against the C compiler's layouts and against graphs written by hand in the shape the vendor
kernel builds them. No real ISP graph has been read by this code and no parameter buffer from it
has reached a running ISP. The `camera.isp/1` driver itself is not in this PR (the stream endpoint
has no read for a config buffer); checks 3 and 4 wait for it.

Run in a local session after this PR merges, on a Rockchip board running the vendor kernel with
`rkcif` and `rkisp` bound and a camera whose kernel sensor driver probes. An RK3588 board (ISP30) is
the first target, an RK3566 or RK3568 board (ISP21) the second, an RV1126B board (ISP35) the third.
Build on NVMe or SSD, never on the Github HDD. Module loads, unbinds and rebinds are allowed; report
each.

## Checks

1. **The graph matches `graph`.** `media-ctl -p -d <dev>` on each ISP media device (driver name
   e.g. `rkisp-vir0`). Pass: entities `rkisp-isp-subdev`, `rkisp-input-params`,
   `rkisp-statistics`, `rkisp_mainpath`, `rkisp_selfpath`; `rkisp-input-params:0 -> isp:1`,
   `isp:2 -> rkisp_mainpath:0`, `isp:2 -> rkisp_selfpath:0`, `isp:3 -> rkisp-statistics:0`, and
   pad 0 fed by the receiver's subdevice. Then a small program reads the topology with
   `lemnos-v4l2` and prints `graph::plan(&t, None, true)`. Pass: the `source` is the entity
   `media-ctl` shows enabled into pad 0, and `enable` lists exactly the links `media-ctl` shows
   without `[ENABLED]`.

2. **The sizes match the running kernel.** On each board, the parameter node's
   `v4l2-ctl -d <rkisp-input-params> --get-fmt-meta-out` and the statistics node's
   `--get-fmt-meta-cap` report `buffersize`. Pass: at least
   `Generation::config_layout().bytes` and `statistics_layout().bytes` for that board's generation
   (ISP21 10475 / 13700, ISP30 10921 / 16172, ISP35 13065 / 14542). If the kernel's headers on the
   board differ from `develop-5.10` (ISP21, ISP30) or `develop-6.1` (ISP35), run
   `drivers/rkisp-sys/layout-check/run.sh` against them and record the diff.

3. **A parameter buffer is taken.** (Waits for the driver.) Queue one parameter buffer of the
   generation's size, all zero but `module_en_update` and `module_ens` set for `AWB_GAIN` with
   unit gains, stream the main path. Pass: frames arrive, `dmesg` shows no rkisp parameter error.

4. **Statistics come back.** (Waits for the driver.) With `RAWAE0` enabled in the parameters,
   dequeue a statistics buffer. Pass: `bytesused` is at most the statistics size and `filled`
   passes it; `frame_id` in the buffer's header (ISP21 and ISP30 at offset 4, ISP35 after the
   statistics) counts up with the frames.

## Not tested here, and known not to be

The `camera.isp/1` driver, the format setup on the ISP's pads, the self path's second link from the
same source pad, ISP32 and every other generation, HDR and multi-camera (`vir1`) modes.
