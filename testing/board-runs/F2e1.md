# F2e1 board check: a receiver that goes away mid-stream stops the sensor

untested on board. The change is in `drivers/ov9782` (`receiver_lost`, `lost_receiver`, the streaming
`tick`, the defensive check in `select_mode`); the host tests in `drivers/ov9782/src/tests.rs` prove it
against a scripted receiver, and two of them fail with the detection disabled.

## Check on the reference board (Raze #2, not yet run)

Take the camera as `testing/board-runs/F2e.md` does (both locks, the product stopped, the stock drivers
unbound, the module loaded, the receiver and back end bound through `driver_override`), start the daemon
with the raw board file, and start a stream of 100000 frames with `lemnos-camera-proof`.

1. Unbind the receiver mid-stream (`echo 1f00110000.csi > .../lemnos-rp1-csi2/unbind`). Pass: within about
   0.2 s the sensor reports Stopped (`lemnos-ctl` shows it not streaming), and the I2C standby write is in
   the sensor's trace.
2. Rebind the receiver and select a mode again: `lemnos-camera-proof --frames 60`. Pass: no `-16`
   (BUSY) from `sensor.select_mode`, and 60 frames arrive.
3. Repeat 1 and 2 five times. Pass: five of five. Record each cycle's result and the module's dmesg lines.
4. Check `dmesg` after the cycles: no warning from the module or the sensor.

Not run. The F2d record's receiver unbind cycles failed 5 of 5 at 3324fec4 with the old driver; that is the
baseline this check must change.
