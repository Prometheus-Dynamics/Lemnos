# I5i5 board run (untested on board)

Nothing here has run on a board. Each check below is for a local board session (the CM5 rules in
AGENTS.md apply: take `/run/lock/board-gpu.lock`, builds on NVMe or SSD, CM5 timings only). Until
they are run, the behaviour they check is verified only by the image and fake-sysfs tests named.

## Checks

1. **The alias is read from the live control tree.** On a U-Boot board, at the U-Boot prompt:
   `fdt addr -c; fdt get value x /aliases mmc1` (and `mmc0`). Expect the SD controller's path, and
   compare it with the board file's `boot_sources` key. Fake-sysfs test: `disk::tests`
   (`the_source_is_the_u_boot_statement_then_the_firmware_boot_mode`).
2. **`fdt set` on `/chosen` survives to the kernel.** Boot a slot whose label has no `fdt` line,
   and read `/proc/device-tree/chosen/lemnos,boot-source` in the running kernel: it must equal the
   path the script set. A missing property is refused by name by slot-init
   (`a_board_that_states_no_boot_source_is_refused_without_touching_a_slot`).
3. **A label with no `fdt` line boots the prepared tree.** `board.dtb` loaded by the script is the
   tree the kernel gets. Check the kernel's model string against the board's `board.dtb`.
4. **Pi family (the CM5, `raze`).** `/chosen/bootloader/boot-mode` reads as code 1 on the eMMC boot
   (measured). Check that the slot-init chain resolves `rpi-boot-mode-1` to the eMMC node
   `/soc@107c000000/mmc@fff000` (sysfs `of_node` of the disk's controller). Codes other than 1 are
   from documentation and are not checked here.
5. **Two media (per board with an SD card and an eMMC).** Boot from the SD card: the resolved boot
   disk must be the SD card (`the boot disk is mmcblk…` in the kernel log, and its controller). Then
   boot from the eMMC with the same image: the resolved disk must be the eMMC. Each with
   `boot_sources` listing both entries.
6. **The reason record.** Arm a trial whose kernel is missing a piece; the kernel log must show the
   reason, and `reason.rec` on the boot partition must hold it after the restart (raw sector, no
   mount). Remove `reason.rec` from the image and the reason is refused by name in the log.
7. **No read-write mount.** During a boot, `mount` lists the boot partition read-only only (the NAND
   UBIFS read is the only one, and it is read-only).

8. **Fall-through and room for the property (U-Boot).** With `boot.scr` built from `boot.cmd`:
   (a) boot normally: the console shows no `going on` line and `fdt set` did not fail (no room error);
   the kernel's `/proc/device-tree/chosen/lemnos,boot-source` is the controller's path.
   (b) delete the default slot's `board.dtb`: the console says `default: cannot load ... going on`
   and the root copy boots; the board never stops at a U-Boot prompt.
   (c) delete the root copy's `board.dtb` too: the console says `root: cannot load ... going on`
   and the script ends (U-Boot's boot flow goes on); I5i7 replaces that end.
   (d) boot from a medium the table does not list: unchanged, the kernel refuses by name.
