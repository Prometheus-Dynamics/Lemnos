# W1 board run: the first-flash write on the CM5

Status: untested on board. The xz and LZMA2 decoder (every check kind, multi-block streams, a
dictionary over the limit, truncation and corruption, the image and record streams, a third stream and
a junk second stream), the signed message and its test vector, the eight rows of the signature policy,
the write, verify and cancel jobs, the running-system refusal, `allow_first_flash`, the memory bound over
a multi-megabyte stream and over a two-stream file, and the bridge's streamed push are covered by tests on
temporary files and a fake mount table (`drivers/system-flash/tests`, `service/orion/tests/flash_stream.rs`).
No image has been written to a real device.

Run in a local session after this PR merges. Take the board lock named in `AGENTS.md`
(`/run/lock/board-gpu.lock`) before starting, use the CM5 only, and build on NVMe or SSD, never on the
Github HDD. Report CM5 timings only.

Use a spare SD card in the CM5's reader, never the board's own boot media. The check writes to the card's
whole device, so the board must be booted from something else (a second card) for the whole run. A
`system-flash` device on the card's block device (its path named only in the board file), with
`allow_first_flash = true`, as the flasher's board file sets it:

```toml
[[devices]]
id = "first-flash"
driver = "system-flash"
config = { path = "/dev/mmcblk1", allow_first_flash = true, max_dict_mb = 8, keys = "/etc/lemnos/flash-keys" }
```

The image is a small whole-disk image built for the card (a partition table, one FAT partition with a
file in it). Build it with `xz -6 --check=crc64 -T1 -k image.img`. Sign it as
[First flash](../../docs/slots.md#first-flash) describes (the record as the file's second stream and in the
transport manifest's `signature` field), and write `image.img.xz.json` with `"format":"disk"`.

1. Refusal before writing. With `allow_first_flash` unset, `write` is refused and `info` says why. The
   card's contents are unchanged (a checksum of its first MiB before and after).
2. Running system. Point the device at the card the board is running from: `write` is refused, with
   the mount named in `info`. Nothing is written.
3. Write. Stream the xz image through the bridge (`LEMNOS_ORION_STREAMS=first-flash=image.img.xz`),
   then the job's result is the image's raw byte count and the signature outcome.
   Pass: the answer is `committed` and says `signature verified`, the card's first MiB matches the image's
   first MiB, and `info` says `written` with `manifest.signed` `verified`.
3a. Unsigned, with signing required. The same image with no record (no second stream, no `signature`
   field) and the security switch on: the manifest is refused before any write, and the card is unchanged.
   Then the same with signing off: `not_checked_unsigned`, accepted.
4. Verify. Run `verify`. Pass: the result is the image's byte count.
5. Corrupt stream. Stream an image whose manifest hash is wrong.
   Pass: the answer is `rejected`, `info` says `failed`, and nothing is booted.
6. Cancel. Cancel a write half way.
   Pass: the job ends cancelled, `info` says `cancelled`, and a re-run writes the whole image.
7. Partition table. After a write, `BLKRRPART` either succeeds, or `info` reports the kernel refused it;
   the card then shows the new partitions after a restart.
8. Memory. Watch the bridge's resident set over a 1 GiB stream.
   Pass: it stays within the decoder's dictionary (8 MiB) plus a few chunks.

Record the card's model and size, the image's size and its xz size, the time each stream took, and the
CM5's CPU and memory figures (timings for the CM5 only).
