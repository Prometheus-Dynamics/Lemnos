# E12 board run: sunxi-vin receiver

Status: untested on board.

No A733 board was reachable from the session that built `drivers/sunxi-vin`. Everything below is
what a local session checks once one is. Take the board lock named in `AGENTS.md`. Build on NVMe or
SSD, never on the Github HDD.

## Source of the interface facts

The vendor kernel's camera driver, from radxa/allwinner-bsp, branch `cubie-aiot-v1.4.6`,
`drivers/vin` (GPL-2.0; facts only, no code copied):

- `vin-video/vin_video.c`: the capture node is `V4L2_CAP_VIDEO_CAPTURE_MPLANE` only
  (`vin_init_video`); `VIDIOC_S_INPUT` (`__vin_s_input`) enables the sensor's link and the
  parser-to-ISP link and opens the pipeline, and comes before `VIDIOC_S_FMT`; closing the node
  disables both links again; lines are `width * depth / 8` bytes.
- `vin-video/vin_core.c`: the raw formats (8 bits per pixel at depth 8, 16 at depths 10 to 16; GREY
  is the only monochrome one). `vin-video/vin_core.h`: frames 32 to 4800 pixels each way.
- `vin.c`: the media graph (`vin_create_media_links`, `vin_setup_default_links`).
- `vin-isp/sunxi_isp.c`: the ISP subdevice's function is `MEDIA_ENT_F_PROC_VIDEO_PIXEL_FORMATTER`.
- `vin-mipi/sunxi_mipi.c`: up to 4 lanes per port.

## What has to hold first

- The vendor kernel's `vin` driver is bound and its capture node appears in a media graph. Record
  `media-ctl -p` for the device, and the capture node's entity name (for example `vin_video0`).
- The stock pipeline sets itself up from its own sensor subdevice: `S_INPUT` and `S_FMT` ask it for
  its bus format and window. Find out whether the board's device tree gives the vin driver a sensor
  module. If the pipeline only works with the kernel's sensor module bound, record that: it means
  the sensor can't be driven only through Lemnos on this block yet, and the run continues with the
  kernel's sensor driver doing the sensor's part.
- A board file entry:

  ```toml
  [[devices]]
  id = "csi0"
  driver = "sunxi-vin"
  config = { capture = "vin_video0", order = "<the sensor's order>", lanes = <wired lanes> }

  [devices.streams.frames]
  buffers = 4
  buffer_bytes = <at least the layout's size>
  ```

## Checks

1. **Bind and configure.** `configure` with the sensor's mode returns the layout. Record it next to
   what `v4l2-ctl -d <node> --get-fmt-video` reports after `start`. Pass: same width, height, pixel
   format and bytes per line, and the node's size image is at least the layout's size.
2. **Bit placement.** At RAW10, capture one frame of a flat bright scene and one of a dark one.
   Record which bits carry the value in each 16-bit word. Pass: the value is in the high bits, as
   `Packing::Unpacked16` says. If it is in the low bits, the driver's `Unpacked16` claim is wrong and
   is fixed before anything else.
3. **Frames through the stream.** With a consumer attached, stream 3000 frames. Pass: sequence
   numbers rise with no gap that the node's own sequence doesn't have, every frame's `bytes` equals
   the layout's size, and the bytes match a capture of the same frames straight from the node
   (`v4l2-ctl --stream-mmap --stream-to`) for a static scene within sensor noise.
4. **No consumer.** Stream with no consumer for 60 s, then attach one. Pass: `counters` shows the
   frames as dropped, the node's frame rate doesn't drop while nobody reads, and the first frames
   after attaching arrive.
5. **Stalled consumer.** Attach a consumer that never returns a buffer. Pass: capture keeps running
   at the sensor's rate, `dropped` rises by one per frame after the stream's buffers are out.
6. **Recovery.** Unbind and rebind the vin platform device while streaming. Pass: health goes
   degraded, attempts back off from 250 ms to 8 s, and streaming comes back after the rebind with no
   call from outside.
7. **Which ISP.** While streaming, call `feeds`. Pass: it names the sensor, the CSI-2 receiver
   entity and the ISP entity that `media-ctl -p` shows enabled on the node's path. Repeat after
   `stop`: the answer stops at the ISP, because the node closed and the kernel took the links down.
8. **Cost.** Record lemnosd's CPU at 30 fps and at the sensor's highest rate, the copy's time per
   frame, and steady-state allocations (expected 0).
