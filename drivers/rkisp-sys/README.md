# lemnos-driver-rkisp-sys

The vendor kernel `rkisp` driver's parameter and statistics buffers for ISP21, ISP30 and ISP35, as
`#[repr(C)]` layouts generated by bindgen, with their sizes and key offsets checked at compile time
against the C compiler's. `no_std`, no dependencies, no device code.

- `isp21`, `isp3x`, `isp35`: bindgen's output (`bindgen.sh`). Do not edit.
- `layout.rs`: the C compiler's sizes and offsets, generated by `layout-check/run.sh`.
- `module`: the ISP21 and ISP30 module bits; `module35`: the ISP35 module bits (46 bits, resolved
  from the ISP35 header's aliases), checked against the C compiler with a throwaway program.
- `bytes`: `Bytes`, a safe byte view of the six buffer structures (`as_bytes`, `as_bytes_mut`,
  `from_bytes`). It reinterprets the packed structure's memory rather than encoding field by field
  as `drivers/pisp` does: the bindgen structures are too large to list by hand, and the view is
  sound because each is `repr(C, packed)` with integer and byte-array fields only.
- `ISP*_PARAMS_BYTES`, `ISP*_STATS_BYTES`: what the driver needs from the layouts.

## Regenerating and checking

The headers are not kept here. From a checkout of rockchip-linux/kernel at `develop-5.10` and one
at `develop-6.1`:

```
./bindgen.sh    <develop-5.10>/include/uapi/linux <develop-6.1>/include/uapi/linux
./layout-check/run.sh <develop-5.10>/include/uapi/linux <develop-6.1>/include/uapi/linux
```

`bindgen.sh` needs bindgen-cli and clang. `run.sh` needs a C compiler and diffs the generated
assertions against `src/layout.rs`.

## Licences

The headers are `(GPL-2.0+ WITH Linux-syscall-note) OR MIT`; the generated modules use them under
MIT, as their headers say. The rest is `MIT OR Apache-2.0`.

## Provenance

The dev branch's `crates/lemnos-rkisp-sys` (its generated `isp21.rs`, `isp3x.rs`, `isp35.rs`,
the layout numbers in `lib.rs` and `isp35_layout.rs`) and `scripts/rkisp-bindgen.sh`. Regenerating
with the same bindgen options gives dev's files exactly, less the `bytemuck` derives this crate
drops. The ISP32 layouts dev also had are not part of this crate.

## Board status

Untested on board: checked against the C compiler, not a running driver.
